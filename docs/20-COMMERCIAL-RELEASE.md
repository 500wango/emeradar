# 20 — 首发商业化产品

Status: Draft for build ｜ 依赖：01 §1.7、05 §5.0、13 §4.4、15、16 ｜ 被依赖：实现与设计伙伴验收

本文把首发要卖的 SaaS 收成一套可以上线的范围。与 01 冲突时以 01 为准。数值阈值仍以 `sc-1.0.0` 为初始值，Phase 0 用真实快照校准。

## 1. 卖什么

独立开发者按月购买的是：在美国英语搜索里，每天看到少数已经观测够久的机会，并完成「做 / 放弃 / 先看着」。判断可以点回证据，上线之后能对回当时那条裁决。

不卖关键词审计，不卖灵感清单，不卖准确率徽章。

## 2. 用户与市场

| 项 | 首发 |
|----|------|
| 买家 | 华语出海的独立开发者，准备做工具站或 Micro-SaaS |
| 研究市场 | `US` / `en-US`，写在每张卡片上 |
| 界面 | 决策层可用英语交付；中文是同一信息架构的本地化，不另做一套结论 |
| 证据 | 查询和标题保持原文 |

## 3. 对象与状态

| 对象 | 用户看见的含义 |
|------|----------------|
| `CANDIDATE` | 已开始观察。没有发布裁决，不在信息流里，不能「做」 |
| `TRACKED` | 通过发布资格，可以出现在信息流 |
| Verdict | `BUILD_NOW` `EARLY_BET` `WINDOW_CLOSING` `WATCH` `PASS` |
| Decision | 用户的 `GO` 或 `PASS`，必须引用当时的 `verdict_id` |
| Project | 只从 `GO` 创建，用来记域名、上线日和之后的结果 |
| Report | 已发布的 `BUILD_NOW` / `EARLY_BET` 的六段卷宗，是 Pro 的导出配额 |

发布资格（05 §5.0）：联想历史不少于 14 天，有一份单一来源的自然搜索结果快照且覆盖不少于 14 天，M 轴不是仅靠查询词推断，关键源没有在本批失败后被当成空结果打分。不满足则 `WATCH` + `PARTIAL_DATA` + 置信度 `LOW` + `CANDIDATE`。

`WINDOW_CLOSING` 只从已经发布的 `BUILD_NOW` 或 `EARLY_BET` 降下来。

## 4. 一天里的产品

1. 新用户回答四问：出货形态、时间预算、市场（默认美国英语）、可选话题。然后进入信息流。
2. 信息流默认 `BUILD_NOW`，每天最多 10 条，按时间预算和形态过滤。`EARLY_BET` 带「商业未验证」。
3. 详情首屏是裁决、三档、置信度、一句 Why Now，以及关注、做、放弃、导出。
4. 「做」写入决策和项目。「放弃」至少选一个原因。关注创建告警，首发邮件触发器是裁决变化、进入窗口关闭、放弃线命中。
5. 用户也可以提交一个查询申请追踪。返回的是观察已开始，不是裁决。
6. 项目页对照的是立项当天的裁决。Search Console 未接通前，展示和点击以自报录入，并标明 `SELF_REPORTED`。

## 5. 三轴在界面上怎么说

| 轴 | 用户看到高档的条件 | 否则 |
|----|--------------------|------|
| D 需求形成 | 至少 14 天联想历史，且 05 的 D 档为 HIGH 或 MEDIUM | `INSUFFICIENT`，不参与 BUILD NOW |
| M 商业证据 | 至少两个独立域名有 observed 定价或结账，规则见 01 §5.6 | 查询词里的商业修饰词最高到 `LOW`，面板写明不证明有人付费 |
| W 进入窗口 | 单一来源自然搜索结果上的弱页、新进入者和拥挤度 | 混合来源样本可以展示，标题不得叫 Google Top 10，W 为 `INSUFFICIENT` |
| 置信度 | 独立来源数、新鲜度、observed 占比 | 关键源失败则为 `LOW`，不发升档裁决 |

详情的商业区固定两栏：证明了什么、不证明什么。没有观测到的支付服务商不得出现在左栏。

弱结果的理由必须能从存下来的字段重算。没有 `published_at` 就不写「过时」。非弱结果只有 `SPECIALIST` 或 `OFFICIAL` 才使用 specialist 标签。

## 6. 套餐

价格在预售访谈前不写死。结账页先列出权益。假设价只出现在内部文档，不出现在官网，直到至少 8 人预付或签意向（01 H3）。

| | Free | Pro |
|--|------|-----|
| 信息流 | 延迟 45 天的公开机会摘要 | 实时，每天最多 10 条已发布决定 |
| 详情 | 摘要 | 完整，含证据抽屉 |
| 报告 | 每月 1 份预览，不可导出 | 每月 30 份，可复制 Markdown、下载 Markdown 与 JSON |
| 关注与告警 | 1 条每日摘要 | 邮件：裁决变化、窗口关闭、放弃线 |
| 项目 | 1 | 50 |
| 申请追踪 | 可以，只产生 `CANDIDATE` | 同左，不扣报告额度 |

Team、开放 API、多席位不在结账页。`api_access` 首发为 false。

降级不删除已有项目和关注；超出上限的部分只读，告警按 13 停用多余规则。

## 7. 公开站

| 页面 | 作用 |
|------|------|
| `/` | 说明决策，展示至多 2 条真实 BUILD NOW，进入信息流 |
| `/methodology` | 发布资格、三轴、什么不算证据 |
| `/pricing` | Free 与 Pro 的权益，价格未定时写「设计伙伴定价」 |
| `/track-record` | 命中和失误、样本数、T+30/60/90 |
| `/opportunities/[slug]` | 仅延迟公开资格通过的机会（15） |

首页禁止：预测准确率、未登记的「数百万查询」、用哈希证明判断正确、虚构收入区间。

## 8. 首发不做

创意配方和收入区间、即时扫词裁决、假趋势曲线、把五路接口编成自然排名、对话助手、多市场、团队版、程序化 SEO 页面、在账本不满 60 天时公开准确率。

新数据源先登记它服务哪一轴、失败时界面说什么，再接入。不能接进同一张 Top 10。

## 9. 上线门槛

沿用 01 Gate，首发对设计伙伴额外验收：

- 任意一个刚提交的查询，详情状态是观察中，裁决不是 BUILD NOW 或窗口关闭。
- 信息流里每条 BUILD NOW 都能打开证据，商业区两栏非空，M 档与证据类别一致。
- 「做」之后项目页能看到当时的裁决编号；「放弃」没有原因则提交失败。
- 首页没有准确率数字。
- Free 账号看不到当天的实时详情全文。

## 10. 实现对照

| 规则 | 落点 |
|------|------|
| 申请追踪不发裁决 | `LiveScanService.scan` 写入 `CANDIDATE` / `WATCH` / `LOW` |
| 信息流不含观察中的行 | `OpportunityService.listFeedCards` 限定 `status = TRACKED` |
| 「做」只接受已发布的 BUILD NOW / EARLY BET | `ProjectService.createProject` |
| 「放弃」必填原因 | `DecisionService.pass` |
| 关注 | 现有 `alert_rules`，类型 `VERDICT_CHANGE` |
| 首页、信息流、详情、定价、方法论 | `apps/web` 对应页面 |
