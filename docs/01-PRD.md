# 01 — 产品需求文档（PRD）

**产品类别**：Search Opportunity Intelligence & Launchpad for Builders  
**文档状态**：v3.1 — 2026-10-18 冻结核心口径（裁决顺序、免费层、配额、槽位移除、凭证核验、成本口径）

**基线声明**：本版是下游规格与代码的唯一基线；下游未同步前，以本 PRD 为准。

**说明**：所有阈值为初始假设，须在 Phase 0 用真实数据校准。实现细节归设计文档。

## 1. 产品概述

### 1.1 要解决的问题
独立 Builder 每次启动一个新站或工具，都要为”做什么”花上数周研究，最终多半靠直觉拍板。他们无法回答三个问题：

1. 搜索需求是不是真的在形成？
2. 竞争窗口是否还开着？
3. 是否已经有人在为这件事付钱？

传统 SEO 工具服务于”已选定关键词后的优化”，趋势工具只告诉你什么在涨。没有工具把**”需求形成 + 竞争窗口 + 商业证据 + AI 建站点火包（怎么开工）”**放进同一个可审计、可即刻出货的决策闭环里。

### 1.2 候选机会从哪来（Candidate Sourcing）

**这是产品能否成立的前置条件**。系统通过以下三条路径发现候选机会：

1. **Google Autocomplete 新增监测（主路径）**
   - 每日对预定义的**种子词库（Seed Query Pool）**进行 autocomplete 扩展，种子词来源：
     - 高意图商业词根（如 “how to”, “best”, “[category] tool”, “[verb] online”）
     - AI 原生词根（如 “chatgpt for”, “ai [noun]”, “gpt wrapper”）
     - SaaS 与工具站常见词根（如 “[category] software”, “[action] app”）
     - **Phase 0 初期由团队手工维护 500 个核心词根**，根据前 4-8 周产出情况调整
   - 每个种子词扩展 10-20 个 autocomplete 建议；按 50-70% 去重/合格率，全池约 **3,000-5,000 个监测词**（原始词 5,000-10,000）
   - 只有在 7 天或 30 天窗口内**首次出现**的新 autocomplete 建议才进入候选池
   - 每日新增候选量预估：10-30 条（Phase 0 用真实数据校准）

2. **用户自定义词（Fast Lane）**
   - Pro 用户每月 15 次自定义词即时初筛，通过初筛的词自动进入 7 天雷达追踪
   - Free 用户终身 1 次自定义词，通过初筛的词进入候选池但不追踪

3. **社区反馈词（Gate 1 之后）**
   - 用户可提交”这个词应该被追踪”的建议，经人工审核后加入种子词库
   - 初期不做，避免被羊毛党污染种子库

**候选池规模与产出预估**：
- 每日新增候选：10-30 条
- 候选→CANDIDATE（观测≥7天）：约 30%（3-9 条/天）
- CANDIDATE→BUILD_NOW + EARLY_BET：约 5-10%（合计每周 1-5 条）

**Phase 0 必须验证**：
- 种子词库能否稳定产出每周 1-5 条 BUILD_NOW + EARLY_BET（需至少 10 周数据，含 T+30 观测）
- 新增 autocomplete 监测的假阳性率（无意义的词组合）
- 扩展一个种子词的 API 成本

**如果 Phase 0 连续 4 周产出 < 1 条 BUILD_NOW**：
1. **立即启动 Plan B**：引入 Google Trends “上升中”榜单作为第四条候选来源（每周手工筛选 20-30 条）
2. 扩大种子词库至 800 个词根（监测池 5,000-8,000 词），SERP 成本增加约 60-70%
3. 激活预定义的 EARLY_BET 快车道（7 天脉冲即可发布；只影响 EARLY_BET，不改变 BUILD_NOW 阈值；作为 Plan B 版本化配置，需 SHADOW 对比）
4. **如果 Plan B 执行 4 周后仍 < 1 条/周**：承认核心假设失败，延长 Phase 0 至 12-16 周重新验证，或暂停进入 Phase 1
5. **不做的选择**：纯爬虫式全网扫描（成本不可控）、依赖第三方关键词数据库（无差异化）、为凑产出降低 BUILD_NOW 阈值到不可信程度

### 1.3 产品定义
**在窗口关闭之前，帮独立 Builder 决定下一个做什么；用可审计的证据支撑判断；交付一份权威的商业机会研究报告与可直接喂给 AI 编译器的工程点火包（Opportunity Report & Launch Kit）；并用公开、不可篡改的预测战绩证明判断是对的。**

### 1.4 差异化与竞争优势

**为什么不让用户自己用 ChatGPT + SERP API 查？**

用户确实可以自己拼凑，但有三个致命摩擦：

1. **时间壁垒**：
   - 用 ChatGPT + SERP API 一次性查一个词，成本几毛钱，但**无法回答"哪些机会正在形成"**
   - 要找到一个值得做的机会，需要监测数百个词、跨 7-90 天观察趋势、对比 SERP 竞争变化
   - 自己做需要每天手动跑脚本、存储快照、写规则判断，**时间成本远超产品订阅费**

2. **数据壁垒**：
   - 我们的核心价值不是"查一个词"，而是**"时间积累的趋势数据"**：
     - 哪些 autocomplete 建议是 7 天内新出现的
     - SERP Top 10 在过去 30 天如何变化
     - 商业信号（定价页、评论数）的增长轨迹
   - 用户一次性查询拿不到这些，必须自己建立监测系统
   - **Phase 0-1（前 6 个月）这个壁垒很薄**，但每多运行一个月，壁垒就厚一分

3. **判断框架**：
   - 我们提供的不是原始数据，而是**"什么时候该做、什么时候该放弃"的决策框架**
   - D/M/W 三轴 + Evidence Confidence 的裁决规则、BUILD_NOW vs EARLY_BET 判断、Kill criteria — 这些是提炼出来的认知，不是 API 返回值
   - 用户自己拼凑，需要从零建立判断标准，大概率会被虚假信号误导

**vs. Exploding Topics / Glimpse / Ahrefs 新功能**：
- Exploding Topics：只告诉你"什么在涨"，不告诉你"窗口是否还开着、是否有人付费、怎么做"
- Glimpse：同样只有趋势，无商业验证
- Ahrefs/Semrush：服务于"已选定关键词后的优化"，不是"选什么关键词"
- **我们的差异化**：四件事放在一起（趋势+竞争+商业+点火包）+ 公开战绩验证

**首发（Phase 0-1）的护城河**：
- 决策框架（D/M/W 三轴 + Evidence Confidence、裁决规则）
- AI 点火包交付（`.cursorrules`、PSEO 词表、Landing 骨架）
- 公开战绩（T+30/60/90 验证）
- **不是**数据壁垒（6 个月内数据积累还很薄）

**18 个月后的护城河**：
- 时间积累的趋势数据（哪些机会形成了、哪些失败了）
- 用户立项后的真实排名爬升数据（Builder-outcome precision）
- 社区反馈的种子词库优化

### 1.5 目标用户（ICP）
| 类型 | 说明 |
|------|------|
| **主要** | 独立开发者 / Micro-SaaS / 工具站 Builder：每月愿意新上线至少 1 个站或工具，熟练使用 Cursor / Claude Code 等现代 AI 工具快速交付 |
| **次要** | Programmatic SEO 运营者（可使用，并可直接消费导出的 PSEO 路由词表） |
| **不服务** | 小型 Growth 团队、Domain 研究员、纯内容 / 联盟站运营 |

> 核心设定：主要用户为华语出海 Builder，首发目标研究市场固定为 `en-US`（美国英语）。见 §12 决策 1。

### 1.6 定价框架与收入模型

**Phase 0 必须敲定的价格**（以下为推导逻辑，非最终值）：

| 档位 | 推导逻辑 | 预估区间 |
|------|---------|---------|
| **Pro 月付** | 对标："Ahrefs Lite $129/月"的 1/2-2/3（功能更窄但决策更聚焦）；用户画像："华语独立开发者，月收入目标 $5k-20k，愿意为省时间付费但对$100+敏感" | **$49-79/月** |
| **Pro 季度 Builder Pass（主推）** | 月付 × 3，约 12-16% 折扣；90 天覆盖"立项→上线→排名爬升"完整周期 | **$129-199/季度** |
| **Pro 年付** | 月付 × 12，约 32-37% 折扣 | **$399-599/年** |
| **Founding Lifetime** | 年付 × 约 3；限额 50 席售罄即止，不承诺未来高成本功能；Founding 固定价 $1,499 | **$1,199-1,999 一次性** |

**Phase 0 必须验证的问题**：
- 访谈 20+ 目标用户，问"看完 Demo 报告和点火包，你愿意付多少钱？"
- 测试两个价格锚点（如 $49 vs $79），看转化率差异
- 确认用户对"每月 3 次立项配额"的感知价值

**收入模型（Gate 1 通过后 18 个月）**：
- Pro 订阅席位上限 30（不含 Founding Lifetime）
- 假设均价 $60/月，30 席 × 18 个月 = **$32,400**（订阅收入）
- Founding Lifetime 50 席 × $1,499 = **$74,950 一次性**
- **总收入预估**：$32,400 + $74,950 = **$107,350**（18 个月）
- 这是**验证阶段，不是业务**；Gate 1 通过后再考虑规模化

**定价的两个硬约束**：
1. **毛利率 ≥ 70%（全成本口径）**：API 数据成本在 500 用户规模下 ≤ $1.00/用户/月，且任何规模下 ≤ 订阅收入的 20%；Phase 1（≤30 席）监测池按 3,000 词/日运行，Gate 1 后扩至 5,000 词/日。完整毛利率以 R7 全成本表为准。
2. **Churn 对抗**：主推季度 Pass（90 天覆盖完整周期）+ 配额跨月结转（Rollover）

### 1.7 非目标
- 不做 Ahrefs / Semrush 的全功能替代；不以 Keyword Difficulty / 反链库为核心。
- 不做无门槛的公开免费无限查词工具。自定义词采用”受严格配额限制的静态初筛 + 7 天时序雷达追踪”双阶段机制。
- 不做创意目录，不展示未经观测的收入区间。
- 不做纯热点新闻工具，不把新闻、代码仓库、问答、百科穿插后称作 Google 自然排名。
- 不依赖单一数据源生存。每个源只服务一条轴，偶发采集失败执行 **72 小时优雅降级（`STALE_DATA`）**，连续失败超过 72 小时该轴才置为 `INSUFFICIENT`。
- 首发不做团队协作、组合管理、多研究市场、开放 API、对话式助手、程序化 SEO 公开页面。MCP Server、CLI 与社区众包校准同属此列；Phase 2 前如要做，先修订本 PRD。

### 1.8 首发商业产品核心规则
首发卖的是每日少数可执行决定、直接可用的建站弹药，以及完整的证据链透明度。完整定价见 §1.6。

1. **发布资格与双轨生命周期**
   - **Evergreen 慢车道（结构型需求）**：观测 ≥ 14 天，且具备至少一个来源的自然搜索快照，置信度 ≥ `MEDIUM`。
   - **Fast-Track 快车道（脉冲型/新生态需求）**：观测历史只需 ≥ 7 天。若 7 天内出现显著爆发斜率（`new_queries_7d ≥ 3` 且加速度拉升）且 SERP 前 5 无绝对龙头，可立即进入快车道评估。
   - 处于观察积累期的记录状态为 `CANDIDATE`，裁决为 `WATCH` 并带 `PARTIAL_DATA`。候选池作为「正在观测的异动流」对 Free 用户只读开放，消除冷启动死寂感。

2. **裁决顺序（单值，先硬性出局，再判窗口）**
   - **先执行 `PASS`**：D=Low、W=Low，或 M 出现强负面信号。
   - **再判 `WINDOW_CLOSING`**：此前已发布裁决为 `BUILD_NOW` / `EARLY_BET`，且 W 在 14 天内下降 ≥1 档（当前 W≥Medium）。窗口关闭是单值裁决，不与 `BUILD_NOW` 叠加；同一机会的新裁决直接覆盖旧裁决。
   - **再判 `BUILD_NOW`**：标准路径 `D≥MEDIUM ∧ M=HIGH ∧ W≥MEDIUM ∧ Confidence≥MEDIUM`；补偿路径 `RULE_BUILD_NOW_COMPENSATED`：`D=HIGH ∧ W=HIGH ∧ M=MEDIUM`，且 M 含 `COMMERCIAL_TRACTION` 或定价持续 ≥90 天。
   - **再判 `EARLY_BET`**：`D=HIGH ∧ W≥MEDIUM`，或快车道 `D≥MEDIUM ∧ W=HIGH`；M 可为 Low / Medium / Insufficient。界面明确标注“商业未验证，抢跑窗口”。
   - **其余为 `WATCH`**：D=Insufficient 时标注 `PARTIAL_DATA`。
   - 优先级：`PASS` → `WINDOW_CLOSING` → `BUILD_NOW` → `EARLY_BET` → `WATCH`。

3. **商业信号真实性**
   - **装饰性定价（`PRICING_DECORATION`）**：仅有定价页或支付按钮，无真实用户与交易痕迹，上限仅为 `LOW`（单站）或弱 `MEDIUM`（多站）。
   - **真实交易代理（`COMMERCIAL_TRACTION`）**：具备用户评价/评论增长（Chrome 插件市场、Shopify App、Trustpilot 等）、社交交易付费讨论、公开 MRR / 销售徽章，或具备可核实自然流量规模。只有具备交易代理或持续营收证据时，M 轴才评为 `HIGH`。
   - **新晋赢家标记（`PROVEN_NEW_ENTRANT`）**：注册/上线不满 6 个月的新独立域名闯入 Top 5 且具备 `COMMERCIAL_TRACTION`，卡片高亮标记，提供最直观的”反向克隆”验证。

4. **产出健康区间**
   - 目标每周稳定输出 1–5 条 `BUILD_NOW` + `EARLY_BET` 合计，严防”0 产出导致漏斗干涸”。
   - **稀缺性硬约束**：过去 30 天新增已发布裁决（含 `WATCH` / `PASS`）中，`BUILD_NOW` 占比 ≤5%；存量占比仅作观察指标，不作为硬约束。
   - 产出低于下限只触发人工复核，**不得为凑产出自动调阈值**；任何阈值变更必须先经 SHADOW 对比验证，且不得追溯修改历史裁决。
   - **如果 Phase 0 连续 4 周产出 < 1 条 BUILD_NOW**：触发 §1.2 应急预案（扩展候选来源、按预定义 Plan B 调整 EARLY_BET，或延长 Phase 0）；`BUILD_NOW` 阈值不变。**兜底承诺在 Gate 0 通过后生效**：连续 2 周全平台合格 `BUILD_NOW` + `EARLY_BET` 为 0 时，自动延长订阅 7 天；Phase 0 期间不承诺”0 产出则延长订阅”。

5. **动作闭环（GO 点火）**
   - Pro 用户选择机会的某一推荐形态点击「GO」，系统扣减 1 次月度立项配额，解锁该形态专属 AI 点火包下载，并创建 Project 壳。
   - **凭证提交并核验通过后**，系统才开始追踪该项目的 SERP 排名爬升（每周 Top 100 查询）；未提交或未核验的 Project 不追踪、不进入公开战绩。
   - **所有权验证（按凭证类型分阶段启用）**：
     - **独立域名 / 着陆页**：Phase 0-1 用页面 meta token（`<meta name="emeradar-claim" content="{token}">`）；Gate 1 后用 DNS TXT 或 meta token 二选一。
     - **应用商店详情页**：用商店开发者账号 OAuth（Chrome Web Store / Shopify Partner）核验；Phase 0-1 暂不支持的类型标 `UNVERIFIED`。
     - **GitHub Release / 仓库**：用仓库根目录 `.emeradar-verify` 文件或 Release asset 中的 token 核验。
     - **未核验凭证**：标 `UNVERIFIED`，不纳入公开战绩统计；Phase 0-1 可用于 design partner 内部验证 H4；Gate 1 后不开启排名周报。只有 `VERIFIED_OWNER` 计入北极星与 Gate 1。
   - **没有强制质押窗口**：上线凭证是自愿提交；核验通过后开启排名追踪，不设逾期惩罚，不扣配额。

6. **付费层与免费层**
   - **Free**：公开战绩大盘、实时候选异动池只读浏览、终身仅 1 次自定义词「即时静态初筛（关键竞争结论与商业证据可见，具体弱结果 URL 与长尾词表打码）」、**每周 1 条「已失去抢跑价值」的案例（准实时发布，含完整证据链与已完成的 T+30/T+90 结果；未完成则标注待更新；若当周无新案例，展示最近一条已公开案例并标注日期）**。Free 不能点 GO，不支持告警。
   - **Pro（支持季度/年度 Builder Pass）**：全量实时信息流、完整详情与证据链、GO 点火与 AI 点火包导出（**每月 3 次，未用完额度结转，结转后余额上限 6 次**）、每月 15 次自定义词初筛与雷达追踪（不结转）、Watchlist 邮件与站内告警（首发；Webhook Gate 1 之后交付）、凭证核验后的 Project 排名追踪与排名周报。
   - **配额设计理由**：ICP 是"每月愿意新上线至少 1 个站"的独立开发者，每月 3 次配额（+ 最多结转 3 次 = 单月最多 6 次）匹配"每月 1-2 个主力项目 + 1-2 个快速试错"的节奏；如果用户 2 个月不用配额，累积 6 次后不再增长，倒逼用户要么用起来、要么取消订阅（避免"永远不续费"的僵尸账号）。

7. **可证伪战绩大盘（Sealed Ledger）**
   - Merkle 树作为底层审计存证，前台底栏留校验入口。
   - 统计口径：汇总统计纳入全部已发布 Episode，包括无人认领的失误，不得只统计已关窗或已退出的机会；逐行明细在「失去抢跑价值」或「完成 T+90 评估」先到时公开；全部统计从 v2 纪元第一条管线写入行起算，种子数据不计入。
   - **Score override 必须作为独立标记的账本行**单独统计，与自动裁决分开展示，防止外界质疑修战绩。
   - **LLM 分类标签加 `label_version`**：新版标签并行存储，不改写旧快照，支持未来升级分类器时比对历史准确性。
   - 前台主打公开 Cohort 战绩大盘（Hit Rate & Accuracy Matrix），系统自动追踪 T+30/60/90 天主词搜索量走势与 SERP 新独立站存活情况。

## 2. 产品原则

| ID | 原则 |
|----|------|
| P1 | **证据先于分数**：任何结论可追到 `evidence_id` + `snapshot_id` |
| P2 | **诚实标签**：证据类别永不混算；“数据不足”不等于“低” |
| P3 | **决策与点火优先**：每个界面回答“做 / 不做 / 怎么用 AI 今晚开工”，而不是堆砌图表 |
| P4 | **出货导向**：产品的成功以用户 7 天上线核验与 30 天排名爬升衡量，不以页面浏览量衡量 |
| P5 | **时间是资产**：快照不可变（含采集时冻结的分类标签）、账本只追加；越早采集越有价值 |
| P6 | **出货后持续价值**：产品价值不止于导出点火包；上线后 30–90 天的收录、排名爬升与迭代反馈才是留存所在，SERP 追踪与周报是核心功能而非附属 |
| P7 | **100% 可重算**：分数与结论由确定性规则和版本化配置基于已冻结快照计算；重算时绝不重新调用 LLM |

## 3. 成功标准

### 3.1 北极星指标
**Verified Active Projects / Month**：过去 30 天内，从机会点击 GO 并提交上线凭证通过所有权核验，且由系统 SERP 管线持续追踪排名演进的项目数（无需强制绑定用户 GSC）。

### 3.2 可证伪假设
| ID | 假设 | 验证方式 | 初始通过线 |
|----|------|----------|-----------|
| H1 | “autocomplete 新增 + SERP 偏弱 + 增长”的早期信号能预测搜索市场的形成 | 预测账本 T+30/60/90。结果事件必须**独立于 D 轴输入**：用第三方词量或 Trends 走势定义的外部需求形成（`ev-1.1`，06 §7），不得用簇扩张 / 新增 query 自证。对照基线：同池随机；Google Trends 上升榜（**必备**）。若 Plan B 把 Trends 上升榜同时用作候选来源，H1 对照改用 Plan B 激活前冻结的 Trends 基线或同池随机，避免处理组与对照组共享信号 | Top-decile 机会的 60 天外部需求形成事件率 ≥ 基线 3×。**Top-decile 定义**：每日评分候选池的前 10%（按每日 10-30 条候选估算，约 7-21 条/周），不是 `BUILD_NOW` 产出。**最小样本量**：50 个 Top-decile 机会；按 7-21 条/周，约 3-7 周可满足，p<0.05 显著性检验。Gate 0 以 T+30 与代理回测判定，T+60 在 Gate 1 前复核。**Phase 0 时长**：6-7 周产出 + 4-5 周 T+30 观测 = 10-12 周；如产出不足触发应急预案，Phase 0 可延长至 16 周 |

### 3.3 指标体系

## 5. 核心概念与决策模型

### 5.1 核心对象
| 对象 | 说明 |
|------|------|
| Opportunity | 一个实体 + query cluster + `market_country` + `research_language` |
| Evidence | 带类别、来源、时间戳的最小事实单元 |
| Snapshot | SERP（默认 Top 10；映射到已核验 Project 的 query 每周一次 Top 100，见 F1 第 1 条） / autocomplete / 商业信号的不可变快照（**含入库时一次性生成并永久冻结的分类元数据**） |
| Verdict | 某个 `scoring_config` 版本在某时点对 Opportunity 的判断 |
| Prediction Ledger | 所有已发布 Verdict 的 append-only 记录；逐行明细在「失去抢跑价值」或「完成 T+90 评估」先到时公开 |
| Project | 用户 GO 后创建的实际项目，绑定上线凭证 URL 与所选形态 |

### 5.2 三个互相独立的语言与地域概念
| 概念 | 含义 |
|------|------|
| `ui_locale` | 界面与系统消息语言（支持 `zh-CN` 与 `en-US`） |
| `research_language` | 关键词、搜索需求、内容分析的目标语言（首发固定 `en-US`） |
| `market_country` | SERP、趋势、商业化与竞争分析对应的国家 / 地区（首发固定 `US`） |

任何一个都不得隐式覆盖另一个。

### 5.3 `first_observed`
时间字段统一为 **首次被本系统观测到（`first_observed`）**，不等同于“世界上首次出现”。界面使用“首次观测”字样；Methodology 页披露观测起始日期与覆盖范围。

### 5.4 证据类别
| 类别 | 含义 | 对商业验证（M 轴）的作用 |
|------|------|--------------------------|
| `observed` | 系统直接观测（定价页、checkout、公开评论/安装计数器、平台披露的销售数据） | 可参与全部评级 |
| `self_reported` | 当事人自报，必须显式标注 | 可参与评级，但不能单独达到 High |
| `third_party_estimate` | 第三方估算，必须显式标注 | 仅展示；无 observed 佐证时权重为 0 |
| `inferred` | 系统推断（如商业意图查询） | 仅可支撑 Low 与 Medium 之间的判断 |

**硬性规则**：仅检测到 Stripe / Paddle / 支付按钮（`PRICING_DECORATION`），只证明“存在变现基础设施”，不等于有真实收入。矛盾证据必须保留并展示，不得被覆盖。

### 5.5 三轴与证据置信度
每轴分档：`High` / `Medium` / `Low` / `Insufficient`（数据不足）。另有 **Evidence Confidence**：High / Medium / Low，由独立来源数、新鲜度、observed 占比决定。

| 轴 | 回答的问题 | 主要输入 |
|----|-----------|----------|
| **D — Demand Formation** | 需求是否在形成 | **Phase 0-1**：autocomplete 新增与增长（7/30/90 天）、query cluster 扩展、跨源关注触发。**Phase 2+（路线图）**：补充 Google Trends 相对趋势值（0-100）与绝对搜索量估算（如 DataForSEO 月均词量），用于判断"市场量级"而非仅"是否在涨"。Phase 0 不做量级评估的原因：种子词库覆盖不足，API 成本线性增加，早期需求验证不依赖绝对搜索量 |
| **M — Commercial Proof** | 是否已有钱在流动 | 商业信号引擎（F7），区分装饰性定价与真实交易代理 |
| **W — Entry Window** | 窗口是否还开着 | SERP 弱度、竞争变化率、权威新进入者 |

### 5.6 M 轴分档规则（初始值，严防僵尸站越级）
- **High**：≥ 2 个独立域名存在 observed 定价 / checkout，且满足以下之一：① 具备 `COMMERCIAL_TRACTION`（如插件安装/评论正增长、公开销售徽章、可核实流量规模或标注的 self-reported 营收）；② 定价 / checkout 在 ≥ 90 天的快照中持续存在，**且在此期间站点的自然搜索排名、评论计数或外链指标存在非零正增长（严格排除无人问津的僵尸定价站）**。
- **Medium**：≥ 2 个独立域名有 observed 定价 / checkout，但尚无交易代理证据或增长痕迹（多站静态 `PRICING_DECORATION`）；或存在 observed 的类目 / 类比验证。
- **Low**：仅有商业意图查询，或仅单个独立站检测到支付 provider。
- **Insufficient**：采样不足（且超出 72 小时故障缓存期）。
- 强负面信号（如竞品下架付费层、公开退款潮）可降档。

### 5.7 Verdict（按顺序评估，首个命中即生效）
| 顺序 | Verdict | 条件（初始值） |
|------|---------|---------------|
| 1 | **PASS** | D = Low，或 M 出现强负面信号，或 W = Low |
| 2 | **WINDOW CLOSING** | 此前已发布的裁决为 BUILD NOW / EARLY BET，且市场 W（SERP 弱度与竞争压力）在 14 天内下降 ≥ 1 档（当前 W ≥ Medium） |
| 3 | **BUILD NOW（标准）** | D ≥ Medium ∧ M = High ∧ W ≥ Medium ∧ Confidence ≥ Medium |
| 4 | **BUILD NOW（补偿）** | `RULE_BUILD_NOW_COMPENSATED`：D = High ∧ W = High ∧ M = Medium，且 M 含 `COMMERCIAL_TRACTION` 或定价持续 ≥ 90 天 |
| 5 | **EARLY BET** | (D = High ∧ W ≥ Medium) 或快车道脉冲下 (D ≥ Medium ∧ W = High)，且 M ∈ {Low, Medium, Insufficient}；界面明确标注“商业未验证，抢跑窗口” |
| 6 | **WATCH** | 兜底：其余所有情况；D = Insufficient 时标 `PARTIAL_DATA` |

目标稀缺性：`BUILD NOW` 占过去 30 天新增已发布裁决（`status = TRACKED` 且通过 §1.8 发布资格的全部裁决，含 `WATCH` / `PASS`）的 ≤ 5%；每周 1–5 条指 `BUILD NOW` + `EARLY BET` 合计。

### 5.8 机会生命周期（市场状态）
`FORMING` → `EARLY_WINDOW` → `CONTESTED` → `MATURE` → `DEAD`

| 转换 | 规则（初始值，配置化） |
|------|-----------------------|
| FORMING → EARLY_WINDOW | D ≥ Medium ∧ W ≥ Medium |
| EARLY_WINDOW → CONTESTED | W 下降 ≥ 1 档，或 Top10 新增 ≥ 2 个 specialist / 权威竞品，或已核验的独立产品 / 落地页 ≥ 3 个 |
| CONTESTED → MATURE | 竞争结构稳定 ≥ 60 天，且 velocity 趋平 |
| 任意 → DEAD | 需求指标下降并持续 ≥ 60 天 |

### 5.9 拥挤度透明度（Crowding Transparency）
公开展示每个机会的竞争拥挤度，不展示虚拟槽位：已核验的独立产品 / 落地页数量、Top10 中 specialist / 权威竞品数量、近 30 天新进入 Top10 的独立站数量。示例：`Web 工具站：Top10 中 4 个 specialist；近 30 天 1 个新进入者；已核验项目 2 个`。这些指标同时用于 `EARLY_WINDOW → CONTESTED` 转换与 F9 告警。

### F1 信号管线与预测账本（低成本、防限流与高可用架构）
**目的**：用极低的边际数据成本构建随时间积累的观测数据壁垒，严防并发限流与偶发爬虫故障抖动。

**核心工程约束（低成本与高可用铁律）**
1. **SERP 深度分层与一鱼多吃**：Google 自 2025 年 9 月停用 `num=100`，取 Top 100 需按 10 条一页计费的 10 次请求。因此默认每次只采 **Top 10**，用于计算 F6（SERP Weakness）；只对**映射到已核验 Project 的 query** 每周采一次 **Top 100**，同一份快照同时更新 W 轴与第 11–100 名的项目排名匹配（F10）。**严禁为追踪用户项目在这次采集之外单独发起重复的关键词 SERP 请求**（ADR-022）。
2. **双通道削峰隔离（Fast Lane vs. Slow Lane）**：
   - **Fast Lane（实时通道）**：仅服务于用户在前端主动触发的「即时初筛」。通过 Postgres 全局令牌桶（`rate_limit_buckets`）严格限制全局最大并发（如 ≤ 5 req/s），且强制经过 **7 天全局去重**——7 天内任何用户查过的相同词，直接复用已落库的 `serp_snapshots` 快照毫秒级返回，API 成本为 0（不引入 Redis，ADR-017）。
   - **Slow Lane（批量巡检通道）**：服务于每日 Opportunity 例行观测与每周战绩回测。100% 采用第三方 SERP 服务商的低价异步队列（Standard / Async Queue API），并将全天任务通过 pg-boss 队列（ADR-003）**均匀打散在 24 小时（1,440 分钟）窗口内匀速执行**，彻底杜绝整点并发尖峰与 429 限流。
3. **采集故障 72 小时优雅降级（Stale-While-Revalidate）**：
   - 单源 Collector 相互隔离。当某条轴的采集器因目标站点改版或代理超时偶发失败时，**默认沿用过去 72 小时内最后一次成功的 Snapshot 分档（界面标注 `STALE_DATA`），不立即将该轴重置为 `INSUFFICIENT`，也不触发错误的 Verdict 降级告警**；仅当连续失败超过 72 小时，才正式降级为 `INSUFFICIENT`。
4. **预测与成本账本**：所有 Snapshot 不可变；每日 Verdict 以 append-only 写入；每次采集记录精确成本并按源/机会/用户汇总。

**成本明细（API 数据成本，不含基础设施、支付手续费与人工支持）**：
- **SERP 采集（共享池 + Project Top 100）**：3,000 词/日 Top 10 × 30 天 = 90,000 次/月；按实测 Live Top 10 **$0.002/次** = **$180/月**；5,000 词/日时 $300/月。500 个已核验 Project 的每周 Top 100 另计约 **$40/月**（异步队列实际单价待 R7 实测）。
- **Fast Lane 初筛**：每月 15 次 × $0.002-0.005/次 = **$0.03-0.075/用户/月**（7 天全局去重后实际更低）。
- **LLM 分类与归并**：**$0.10-0.15/用户/月**（仅入库阶段，不重复调用）。
- **商业信号探测**：**$0.05/用户/月**（Product Hunt / HN / GitHub API）。
- **合计**：500 用户规模 **$0.62-0.96/用户/月**（共享池 $0.44-0.68 + 其他 $0.18-0.28）；30 席规模 **$6.2-10.4/用户/月**（共享池按 3,000-5,000 词/日摊薄）。
- **成本占收入**：30 席规模按 3,000 词/日约 **8-13%**；若按 5,000 词/日约 **13-21%**（超过 20% 时须提价或扩席）；500 席规模约 **1-2%**。完整毛利率（含基础设施、支付、支持）以 04 §6.3 R7 成本表为准，硬约束 ≥70%。

**验收**：任意历史日期的 Verdict 可 100% 复现（Gate 0 做一次 v2 纪元全量重算）；500 活跃用户规模下，月度 SERP API 总成本 ≤ **$340**（约 $0.68/用户/月），API 数据成本 ≤ 订阅收入的 5%；30 席规模按 3,000 词/日运行，API 数据成本 ≤ 订阅收入的 20%。以 04 §6.3 的 R7 成本表实测为准；反推不成立时 Gate 0 不通过。

### F2 机会引擎（确定性重算与 LLM 快照冻结）
**需求**
- **快照标签入库冻结（消除 LLM 重算不确定性）**：LLM 仅允许在数据采集入库阶段（Ingestion Phase）参与实体归并候选与 SERP 结果类型分类（specialist / UGC / official / weak），其输出的分类标签必须通过 schema 校验并**作为不可变 Snapshot 的静态字段永久冻结落库**。
- **100% 确定性评分引擎**：F2 评分引擎在计算或历史重算（Re-scoring）三轴分档与 Verdict 时，**仅读取 Snapshot 中已冻结的静态分类标签与确定性数值，重算过程严禁再次调用 LLM**，从而确保同一 Snapshot 集合 + 同一 `scoring_config` 版本在任何时间重跑均 100% 得出完全一致的分数与结论。
- 自动识别并标记 `PROVEN_NEW_ENTRANT`（上线 < 6 个月、进入 Top 5 且具备真实交易信号的独立站）。

### F3 Opportunity Feed 与「即时初筛沙盒」
**需求**
1. **主信息流**：只列出通过发布资格的机会。默认 Tab 为 `BUILD NOW`；另有 `EARLY BET` / `WATCH 变化` / `WINDOW_CLOSING` 及只读的「实时候选异动池（Watching Queue）」。
2. **两阶段自定义词初筛沙盒（替代纯等待）**：
   - 搜索框下方预置 **3 个官方示例热词（Demo Queries）**，点击直接零成本读取缓存展示完整初筛效果。
   - 用户输入自定义词时，弹窗确认消耗额度（Free 用户提示消耗**终身唯一 1 次**免费额度；Pro 用户扣除月度初筛配额）。
   - **第 1 阶段（即时静态初筛卡：缓存命中 <1s；实时采集 <8s）**：调用 Fast Lane 实时探针，当场返回静态 SERP 弱结果数与独立站收款探针结论；前端显示扫描进度。
     - **Free 用户半遮罩展示（Blurred Reveal）**：清晰展示“发现 N 个弱结果 + M 个收钱独立站 + 静态切入难度”以制造 Aha Moment；但对**具体弱结果 URL、收钱竞品域名、15 个高意图扩展长尾词进行高斯模糊打码**，引导升级 Pro 解锁。
   - **第 2 阶段（7 天动态脉冲雷达）**：Pro 用户可将初筛通过的词一键加入 `CANDIDATE` 快车道高频监测，一旦 7 天内确认需求脉冲斜率达标，第一时间以邮件与站内通知推送抢跑通知（Webhook 在 Gate 1 之后交付，F9）。

### F4 Opportunity Detail
**首屏（无需滚动）**：Verdict、D-M-W 分档、Confidence、`PROVEN_NEW_ENTRANT` 徽章（如有）、研究市场（en-US）、一句 Why Now、主操作按钮组：
- **「选择形态并立项（GO & Export Launch Kit）」**：原子操作按钮，点击后选择具体 Build Archetype，扣减 1 次月度导出配额，并立即解锁下载该形态专属的 AI 点火包与研究报告。
- 辅助操作：PASS（需选理由） / Watch。

**正文按决策顺序**：
1. Why Now 与跨源动量
2. Search Formation：新增 query、intent cluster、7/30/90 天变化、query graph
3. SERP Intelligence（F6）：具体弱结果列表与新晋赢家解剖
4. Commercial Proof（F7）：含 **What this proves / What this does not prove** 及竞品定价锚点
5. What to Build：推荐 Build Archetype（≤ 3），展示各形态 MVP 范围、技术复杂度、执行规模（S/M/L）
6. Monetization 路线：Primary / Secondary / Not recommended
7. **Kill criteria**：≥ 2 条明确的止损放弃条件，可一键转为 Watch 告警
8. **Pre-mortem**：最可能的失败原因，引用证据
9. 评分分解：由确定性规则渲染

### F5 Compare
- Web 支持 2–3 个机会并排对比：Verdict、三轴、新晋赢家数量、推荐形态与执行规模、Kill criteria 状态。

### F6 SERP Intelligence
- 每个被追踪 query 保存 Top 10 快照（映射到已核验 Project 的 query 每周一次 Top 100，F1 第 1 条）；针对 Top 10 解析结果类型（入库时冻结）、域名年龄/权威分类、相关性、新鲜度，以及 specialist / UGC / official / weak 结果数量。
- **列出具体的弱结果证据**（例如“第 3 位是 2022 年无人维护的 Reddit 帖”），并高亮近 6 个月新闯入 Top 10 的独立站域名。

### F7 Commercial Signal Engine
- 严格区分 `PRICING_DECORATION`（仅检测到支付按钮/定价页，无增长痕迹）与 `COMMERCIAL_TRACTION`（评论增长、销售计数、可验证流量）。
- 支持 direct / category / analog 三级验证，保留历史商业快照与矛盾证据。
- 构造测试集覆盖“仅检测到支付 provider 的僵尸站”“存在矛盾证据”“估算无佐证”三类情形，M 轴均不得越级为 High。

### F8 机会研究报告与 AI 建站点火包 (Opportunity Report & Launch Kit)
**目的**：消除”看完报告还要自己写 PRD 和整理词表”的摩擦，让 Builder 复制粘贴进 Cursor / Claude Code 即可当天开工。**（须通过点击 GO 后方可导出）**。

**交付物一：权威商业决策报告（面向人阅读，6 个板块）**
1. Executive Summary、2. Demand Intelligence、3. Commercial Evidence、4. SERP Weakness Audit、5. Strategic Archetype、6. Risk & Kill Criteria。（90% 确定性装配，LLM 仅生成 ≤ 500 字摘要，支持 Markdown / PDF / JSON 导出）。

**交付物二：Vibe Coding AI 建站点火包（按所选 Build Archetype 动态装配）**
1. **`CLAUDE.md` / `.cursorrules` 工程规范文件**：基于该机会的 SERP 竞品弱点与用户认领的具体形态（如 Web 工具站或 Chrome 插件），自动装配项目技术栈建议、核心功能 MVP 边界、UI/UX 避坑指南与完整开发 Prompt。
2. **Programmatic SEO 路由与种子词表（CSV / JSON）**：将该机会下的 query cluster 自动转化为可直接导入 Next.js / Astro 的动态路由数据结构（包含 `slug`、目标关键词、搜索意图分类、建议 `<title>`、`<h1>` 与 Meta Description 模板）。
3. **高转化 Landing Page 骨架文案（Markdown）**：基于 F7 已验证的竞品痛点与定价区间，生成经过商业证据锚定的 Hero Section、痛点对比矩阵、FAQ（覆盖长尾问题）及 Pricing Tier 建议文案。

### F9 Watchlist 与 Alerts
- 触发器：Verdict 变化（排除 `STALE_DATA` 缓存期）、自定义初筛词 7 天脉冲确认、WINDOW CLOSING、**同一机会已核验项目数达到拥挤阈值（≥3）或新进入者进入 Top10**、**Kill criteria 命中**、已立项凭证在 SERP 出现显著排名跃升（如进入 Top 100 / Top 30 / Top 10）。
- 渠道：首发只交付 Email（含站内通知）；通用 Webhook（内置 Slack / Discord / Telegram 模板）在 Gate 1 之后交付。首发触发器即以上 6 条，不额外扩展。

### F10 Project 凭证提交与无感 SERP Outcome Tracking
**目的**：让 Builder 自愿提交上线凭证，核验通过后开启排名追踪，解决出海站长”闷声发财不愿授权 GSC”的信任摩擦，同时保证战绩数据的真实性。

**需求**
- **自愿凭证提交**：用户点击 GO 导出点火包后，可随时回填已上线的项目凭证 URL。系统支持 3 类凭证：
  1. **独立域名 URL**（适用于 Web 工具站 / PSEO 目录站）；
  2. **官方应用商店详情页 URL**（适用于 Chrome Web Store 插件、Shopify App 等）；
  3. **公开的产品着陆页 / GitHub Release URL**（适用于 API / CLI / 桌面工具）。
  提交是自愿行为，没有时间限制，没有惩罚。凭证核验通过后开启 SERP 排名追踪，未提交或未核验则不追踪。
- **所有权核验（按凭证类型，分阶段启用）**：
  | 凭证类型 | Phase 0-1（简化） | Gate 1+（强制） |
  |---------|------------------|----------------|
  | 独立域名 / 着陆页 | 页面 `<meta name="emeradar-claim">` | DNS TXT 或 meta token |
  | 应用商店详情页 | 商店开发者账号 OAuth（Chrome Web Store / Shopify Partner）；暂不支持时标 `UNVERIFIED` | 商店开发者账号 OAuth |
  | GitHub Release / 仓库 | 仓库根目录 `.emeradar-verify` 或 Release asset 中的 token | 同左 |
  | 无法核验 | 标 `UNVERIFIED`，不进入公开战绩 | 不开启排名周报，不进入公开战绩 |
  只有 `VERIFIED_OWNER` 计入北极星、Gate 1 与公开战绩；未核验凭证不参与排名追踪统计。
- **零成本 SERP 排名无感追踪**：系统每周对映射到已核验 Project 的 query 执行一次 Top 100 采集（F1 第 1 条），匹配该 Project 的域名或商店链接，生成自然排名爬升曲线（如：未入榜 → 第 68 名 → 第 12 名），作为 Builder-outcome precision 与公开战绩大盘的客观依据。
- **GSC 只读 OAuth（可选增强项）**：供愿意深度复盘精细曝光/点击数据的用户自愿连接，不做强制要求。

### F12 Onboarding 与国际化
- **Onboarding**：至多 4 问——Build 偏好、目标市场（默认固定 en-US）、感兴趣领域（可选）、**时间预算**（周末 / 两周 / 一个月，映射到执行规模 S/M/L）。
- **国际化**：UI、报告与 AI 点火包说明支持 `zh-CN` 与 `en-US`；但生成的 PSEO 词表、Landing Page 文案与原始关键词严格保持目标研究市场语言（`en-US`）。

### F13 公开获客层
见 §7。

### F14 管理后台与防白嫖滥用检测（首发最小集）
- Source health（含 72h `STALE_DATA` 状态监控）、collector 失败监控与成本仪表盘（区分 Fast Lane 与 Slow Lane 消耗）。
- 人工机会审核队列、Score override（带审计）、`scoring_config` 版本管理。
- **防白嫖与反滥用硬约束（Anti-Abuse Engine）**：
  - **邮箱归一化与黑名单**：拦截一次性临时邮箱（Temp Mail）；对 Gmail 等主流邮箱执行 Canonical 归一化（自动剥离 `+` 别名后缀与 `.` 符号，映射为同一自然人）。
  - **OAuth 强绑定 + 设备指纹限流**：激活 Free 层”终身唯一 1 次”实时初筛额度，强制要求通过 **GitHub 或 Google OAuth** 登录，并以设备指纹为主做限流（同一设备 30 天内最多触发 1 次免费实时初筛）。IP 只作风险信号，不单独拒绝，避免误伤共用代理出口的华语 Builder；拿不到设备指纹时，要求 OAuth 账号注册满 30 天，否则拒绝免费初筛。

### 7.1 原则
- **失去抢跑价值后公开 + 公开战绩验证**。彻底废除旧版“45 天延迟公开”和 v3.0 草案的“固定 14 天延迟”规则；Free 每周获得 1 条刚进入「失去抢跑价值」状态的案例（准实时发布，含完整证据链与已完成的 T+30/T+90 结果），实时 `BUILD_NOW` / `EARLY_BET` 100% 留给 Pro。

### 7.2 页面范围（首发）

- Pricing、Methodology、Data Sources、Login / Signup。

## 8. 商业模式、防流失包装与单位经济

### 8.1 套餐与防流失包装（对抗”建站开发期退订”）
独立开发者选定项目后会有 2–4 周的开发冷启动期，传统高频查词配额（如每月 30 份报告）会导致极高的次月退订率。因此采用**”配额跨月累计（Rollover）+ 季度 Pass + Founding Lifetime”**设计：

| 权益维度 | Free（体验与防白嫖层） | Pro（独立 Builder 主力层） |
|---------|----------------------|--------------------------|
| **实时机会流 (Feed)** | 每周 1 条已失去抢跑价值的案例（准实时，含已完成的 T+30/T+90 结果）+ 候选池只读 | 全量实时 `BUILD_NOW` / `EARLY_BET` 信息流 |
| **自定义词即时初筛** | **终身仅 1 次**（结果半遮罩打码，需 GitHub/Google 登录） | **每月 15 次**（全量解锁底牌 + 可转 7 天脉冲雷达） |
| **立项与 AI 点火包导出** | 每月 1 份历史报告在线预览（无点火包、不可导出） | **每月 3 次 GO 点火（扣配额 + 导出 AI 点火包）**（未用完额度结转下一期，结转后余额上限 6 次） |
| **自动化追踪与告警** | 不支持 | 邮件与站内告警（Webhook 在 Gate 1 之后）+ 凭证核验通过后每周 SERP Top 100 自动追踪 |

- **季度 Builder Pass（主推档位）与对赌兜底承诺（De-risking Guarantee）**：
  - 主推季度订阅（90 天恰好覆盖”立项 → Vibe Coding 7 天上线 → 30/60 天 SEO 排名爬升”的完整周期）。
  - **兜底承诺（Gate 0 通过后生效）**：只保留一条可计量的触发条件：连续 2 周全平台合格 `BUILD_NOW` + `EARLY_BET` 为 0 时，自动延长订阅 7 天。补偿只给时长或额度，不退现金。触发条件不由团队可调的阈值决定。Phase 0 期间不承诺。
- **供给约束**：Phase 1 期间 Pro 订阅席位上限 30（不含 Founding Lifetime）；Founding Lifetime 50 席独立计数，总服务人数上限 80。Gate 1 后按实测的月均产出数量重算定价与席位。
- **Founding Lifetime**：一次性付款 **$1,499**，复用 Pro 权益与月度配额，**限额 50 席**，售罄即止；不占 30 个 Pro 订阅席位；不承诺无限报告、无限抓取或未来高成本功能。

### 8.2 单位经济约束（Unit Economics）
- 目标毛利率 **≥ 70%**（全成本口径）。
- API 数据成本双重约束：500 用户规模下 **≤ $1.00/用户/月**；任何规模下 **≤ 订阅收入的 20%**。
- Phase 1（≤30 席）监测池按 **3,000 词/日**运行；Gate 1 后按席位与收入扩至 **5,000 词/日**。依托 F1 的“SERP 深度分层”、“7 天全局去重”与“24 小时异步低价队列”控制成本。
- 成本表以 04 §6.3 的 R7 全成本表为准；当前按实测 Live Top 10 `$0.002/次` 保守估算。

## 9. 非功能需求与数据治理

### 9.1 质量与确定性
- 所有推荐可解释；所有 Verdict 基于入库冻结的 Snapshot 标签 100% 确定性可重算；所有历史状态可回放。
- LLM 输出必须经 schema 校验，且事实性内容必须引用 `evidence_id`；AI 点火包中的硬数据（搜索动量、竞品价格、长尾词表）100% 由确定性模板注入，严禁 LLM 自由编造。

### 9.2 数据源合规与隐私保护
- 每个数据源须登记：获取方式、ToS 风险等级、单位成本、72h 降级方案。
- 用户提交的 Project 上线凭证 URL 默认严格保密（公开战绩大盘仅展示脱敏统计与排名跃升幅度，绝不暴露具体域名或商店链接，彻底打消站长顾虑）。

### 9.3 性能与可用性
- Feed / Detail p95 < 1.5s（缓存后）。
- 即时静态初筛（Fast Lane）：缓存命中 < 200ms；实时采集返回 < 8s（配前端扫描进度反馈）。

## 10. 交付计划与 Gate

> 时间按 2–3 人团队（或 1 人 + 重度 AI 编程辅助）估算。

| 阶段 | 内容 | 大致周期 |
|------|------|---------|
| **Phase 0 验证** | F1（双通道管线 + 72h 降级）、F2（快照标签冻结与确定性引擎）、F6/F7 最小评分闭环（W/M 轴）；预测账本上线；成本模型实测；20+ 访谈；20 份人工装配的报告与 AI 点火包样本 | ~10–12 周（6–7 周产出 + 4–5 周 T+30；如产出不足可延长至 16 周） |
| **Phase 1 私测 → 公测** | **Gate 1 必须（在 F1/F2 已交付基础上）**：F3（Feed + 异动 Badge）、F4（Detail + GO）、F6（SERP Intelligence）、F7（商业信号）、F8（报告 + 点火包）、F9（邮件 / 站内告警）、F10（凭证核验简化版 + 排名追踪）、F12（Onboarding / i18n）、F13（公开获客层）、F14 最小集（限流与反滥用）。**可延后至 Phase 2**：F5（Compare）、F14 强化、Webhook。10 → 30 个 design partner（Gate 1 前 ≥30） | ~7–8 周（Gate 1 必须） + 3-4 周（延后功能） |
| **Phase 2 扩展** | F5（Compare）、Webhook、F14 强化、历史回放、对话式 Copilot、zh-CN 研究市场、更多 Build Type | 视 Gate 1 结果 |
| **Phase 3 规模化** | Programmatic SEO / GEO 规模化获客 | 视 Gate 2 结果 |

### Gate 0（进入 Phase 1）
- H1 达到通过线，或有明确的信号修正方案
- 实测 API 数据成本满足 §1.6 的 API 成本约束（任何规模 ≤ 订阅收入 20%；500 用户规模 ≤ $1.00/用户/月），完整毛利率 ≥70% 以 R7 全成本表为准
- H3 达成：≥ 8 人预付或签意向
- 机会报告与 AI 点火包 rubric 通过率 ≥ 80%

### Gate 1（公开发布）
- 预测账本已运行 ≥ 60 天（从 v2 纪元第一条管线写入行起算），战绩页包含真实命中与失误
- ≥ 30 个活跃 design partner，**GO 后 30 天内提交并核验通过的上线凭证率 ≥ 30%**，且 **已核验项目中 30 天内 SERP Top 100 入榜率 ≥ 30%**
- 已有付费用户（≥ 10）

### Gate 2（进入 Phase 3）
- “Demo 体验 → 终身 1 次半遮罩初筛 → Pro 付费”核心漏斗转化率跑通
- ≥ 30 个已核验项目完成至少 30 天的 SERP 排名无感追踪，可对外发布真实的 Builder-outcome precision
- 季度 Pass 购买占比与次月留存达到目标

## 11. 风险与缓解

## 12. 已确认与待决策事项

1. **ICP 与研究市场（已确认）**：主要用户为华语出海 Builder，首发研究市场锁定 `en-US / US`。
2. **免费层与防白嫖策略（已确认）**：废除 45 天延迟与固定 14 天延迟两种旧方案；采用"每周 1 条已失去抢跑价值的准实时案例 + 终身仅 1 次半遮罩即时初筛（强绑定 OAuth 防刷）"。
3. **动作闭环（已确认）**：Pro 用户点 GO 创建 Project 壳并解锁 AI 点火包；凭证按类型核验通过后才开启排名追踪；只有 `VERIFIED_OWNER` 计入北极星、Gate 1 与公开战绩（Phase 0-1 的 `UNVERIFIED` 仅可用于 H4 内部验证）。
4. **成果追踪与高可用管线（已确认）**：默认采用自身 SERP 管线追踪用户项目排名（对映射到已核验 Project 的 query 每周一次 Top 100，F1 第 1 条）；LLM 分类标签在入库时冻结并带 `label_version`；单源故障执行 72 小时缓存降级。
5. **裁决顺序（已确认）**：先 `PASS` 硬性出局，再按 `WINDOW_CLOSING` → `BUILD_NOW` → `EARLY_BET` → `WATCH` 判定；`WINDOW_CLOSING` 是单值裁决，不与 `BUILD_NOW` 叠加。
6. **数据源选型（待 Phase 0 最终敲定）**：SERP 异步队列与实时接口供应商组合（如 DataForSEO + Serper.dev 互备）。
7. **定价（已定义框架，具体值待访谈后敲定）**：参见 §1.6 定价框架；区间已定，具体值在 20 次用户访谈后敲定。
8. **候选来源（已定义，待验证）**：见 §1.2；Phase 0 验证种子词库是否稳定产出每周 1-5 条 `BUILD_NOW` + `EARLY_BET`。
9. **已删除的机制（已确认）**：v3.0 移除独占买断（Stealth Lock）、槽位质押（Commitment Stake）、形态锁槽（Archetype-Level Slotting）与待付占位锁。理由：在 0 付费用户阶段为想象中的拥挤过度设计，保护的 Alpha 在 §1.4 已论证为虚假；槽位只约束诚实用户，真实竞争发生在整个互联网。本 PRD 已清除所有生效中的槽位/质押/买断引用（仅保留删除说明）；全部下游文档（00、02–21、24、25、31）与代码的同步另列迁移任务，未同步前以本 PRD 为准。
10. **配额（已确认）**：Pro 每月 3 次 GO 点火，未用完结转，结转后余额上限 6 次。
11. **Top-decile 与 Phase 0 样本（已确认）**：Top-decile = 每日评分候选池前 10%（约 7-21 条/周），不是 `BUILD_NOW` 产出；50 个样本约 3-7 周；Phase 0 10-12 周（含 T+30），最多延长至 16 周。
12. **成本口径（待 R7）**：PRD 只写 API 数据成本；完整毛利率 ≥70% 以 04 §6.3 R7 全成本表为准。

## 13. 附录：核心术语表
| 术语 | 含义 |
|------|------|
| D / M / W | Demand Formation / Commercial Proof / Entry Window 三轴 |
| `PRICING_DECORATION` | 装饰性定价（仅有价格页或支付按钮，无真实交易痕迹或增长，含僵尸定价站） |
| `COMMERCIAL_TRACTION` | 真实交易代理信号（评论增长、安装量、销售徽章等可核实动态证据） |
| `PROVEN_NEW_ENTRANT` | 新晋赢家（上线不满 6 个月、闯入 SERP Top 5 且具备真实交易信号的独立站） |
| `STALE_DATA` | 采集器偶发故障时，在 72 小时宽限期内沿用最近一次成功快照的优雅降级状态 |
| Launch Kit（AI 点火包） | 与点击 GO 原子绑定的导出物，含 `.cursorrules / CLAUDE.md`、PSEO 路由词表 CSV 与高转化着陆页文案骨架 |
| `label_version` | LLM 分类标签的版本号；新版标签并行存储，不改写旧快照，支持未来升级分类器时比对历史准确性 |
| Score Override | 人工裁决覆盖；必须作为独立标记的账本行单独统计，与自动裁决分开展示 |
| `失去抢跑价值` | verdict 为 `WINDOW_CLOSING` / `PASS`，或 lifecycle 为 `CONTESTED` / `MATURE` / `DEAD`，或连续 14 天不再是 `BUILD_NOW` / `EARLY_BET`；这是 Free 每周案例与逐行明细公开的判据 |
| Top-decile opportunity | 每日评分候选池中评分前 10% 的机会（约 7-21 条/周）；无论最终 verdict，均以 `TRACKED` 写入预测账本用于 H1 回测，不进入公开 Feed |
| `VERIFIED_OWNER` / `UNVERIFIED` | 凭证核验状态；只有 `VERIFIED_OWNER` 计入北极星、Gate 1 与公开战绩 |
| Seed Query Pool | 种子词库；系统每日对其进行 autocomplete 扩展，发现新增候选机会的起点 |
