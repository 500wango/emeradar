# 01 — 产品需求文档（PRD）

**产品类别**：Search Opportunity Intelligence & Launchpad for Builders  
**文档状态**：v2.2 — 2026-10-17 合入设计审查裁决（Q1–Q15，见 `30-REVIEW-REMEDIATION-PLAN.md` §4）；v2.1 为上一版  
**说明**：文中所有数值阈值均为初始假设，须在 Phase 0 用真实数据校准，并写入版本化的 `scoring_config`。

## 1. 产品概述

### 1.1 要解决的问题
独立 Builder 每次启动一个新站或工具，都要为“做什么”花上数周研究，最终多半靠直觉拍板。他们无法回答三个问题：

1. 搜索需求是不是真的在形成？
2. 竞争窗口是否还开着？
3. 是否已经有人在为这件事付钱？

传统 SEO 工具服务于“已选定关键词后的优化”，趋势工具只告诉你什么在涨。没有工具把**“需求形成 + 竞争窗口 + 商业证据 + AI 建站点火包（怎么开工）”**放进同一个可审计、可即刻出货的决策闭环里。

### 1.2 产品定义
**在窗口关闭之前，帮独立 Builder 决定下一个做什么；用可审计的证据支撑判断；交付一份权威的商业机会研究报告与可直接喂给 AI 编译器的工程点火包（Opportunity Report & Launch Kit）；并用公开、不可篡改的预测战绩证明判断是对的。**

### 1.3 目标用户（ICP）
| 类型 | 说明 |
|------|------|
| **主要** | 独立开发者 / Micro-SaaS / 工具站 Builder：每月愿意新上线至少 1 个站或工具，熟练使用 Cursor / Claude Code 等现代 AI 工具快速交付 |
| **次要** | Programmatic SEO 运营者（可使用，并可直接消费导出的 PSEO 路由词表） |
| **不服务** | 小型 Growth 团队、Domain 研究员、纯内容 / 联盟站运营 |

> 核心设定：主要用户为华语出海 Builder，首发目标研究市场固定为 `en-US`（美国英语）。见 §12 决策 1。

### 1.4 用户核心决策
用户不是来“查词”，而是来完成四个决策并直接点火出货：

**做不做 → 为什么 → 做什么形态（含克隆谁） → 拿走点火包当天开工。**

### 1.5 差异化
1. **时间戳证据链与新晋赢家雷达**：每条结论可追溯到 `evidence_id` 与不可变快照，没有黑盒分数；直接揪出近期刚跑通变现的“新晋独立站赢家（`PROVEN_NEW_ENTRANT`）”。
2. **诚实的商业信号分级**：observed / self-reported / estimate / inferred 严格分类，永不混算；明确“这些证据证明了什么、没有证明什么”。
3. **Vibe Coding 点火包交付**：不止于阅读型报告，直接导出面向 Cursor / Claude Code 的工程规则（`.md`）、PSEO 路由词表（CSV/JSON）与高转化 Landing Page 骨架。
4. **防公地悲剧与公开战绩**：按产品形态锁槽、支持零认领状态下的一键独占买断；通过系统自身 SERP 管线无感追踪项目排名爬升，预测账本公开命中与失误。

### 1.6 非目标
- 不做 Ahrefs / Semrush 的全功能替代；不以 Keyword Difficulty / 反链库为核心。
- 不做无门槛的公开免费无限查词工具。自定义词采用“受严格配额限制的静态初筛 + 7 天时序雷达追踪”双阶段机制。
- 不做创意目录，不展示未经观测的收入区间。
- 不做纯热点新闻工具，不把新闻、代码仓库、问答、百科穿插后称作 Google 自然排名。
- 不依赖单一数据源生存。每个源只服务一条轴，偶发采集失败执行 **72 小时优雅降级（`STALE_DATA`）**，连续失败超过 72 小时该轴才置为 `INSUFFICIENT`。
- 首发不做团队协作、组合管理、多研究市场、开放 API、对话式助手、程序化 SEO 公开页面。MCP Server、CLI 与社区众包校准同属此列；Phase 2 前如要做，先修订本 PRD（v2.2，Q13）。

### 1.7 首发商业产品核心规则
首发卖的是每日少数可执行决定、直接可用的建站弹药，以及对抢跑者 Alpha 的独占保护。完整包装见 `20-COMMERCIAL-RELEASE.md`。这里锁定核心业务规则：

1. **发布资格与双轨生命周期**
   - **Evergreen 慢车道（结构型需求）**：观测 ≥ 14 天，且具备单一来源自然搜索快照，置信度 ≥ `MEDIUM`。
   - **Fast-Track 快车道（脉冲型/新生态需求）**：观测历史只需 ≥ 7 天。若 7 天内出现显著爆发斜率（如 `new_queries_7d ≥ 3` 且加速度拉升）且 SERP 前 5 无绝对龙头，可立即进入快车道评估。
   - 处于观察积累期的记录状态为 `CANDIDATE`，裁决为 `WATCH` 并带 `PARTIAL_DATA`。候选池作为「正在观测的异动流」对试用及免费用户只读开放，消除冷启动死寂感。
2. **窗口关闭有前置裁决**
   - `WINDOW_CLOSING` 只可能来自一条已经发布的 `BUILD_NOW` 或 `EARLY_BET`，且**市场 W**（SERP 弱度与竞争压力，不含平台认领拥挤项）在 14 天内下降至少一档，或认领槽位已满触发 `CROWDED_LOCKED`。当天竞争看起来不强，不是窗口关闭。平台内的认领拥挤只经 `CROWDED_LOCKED` 生效，不得经 W 降档制造窗口关闭（v2.2，Q2）。
3. **商业信号真实性（防“有人收费 ≠ 有人付费”）与新晋赢家识别**
   - **装饰性定价（`PRICING_DECORATION`）**：仅有定价页或支付按钮，无真实用户与交易痕迹，属于弱信号，上限仅为 `LOW`（单站）或弱 `MEDIUM`（多站）。
   - **真实交易代理（`COMMERCIAL_TRACTION`）**：具备用户评价/评论增长（Chrome 插件市场、Shopify App、Trustpilot 等）、社交交易付费讨论、公开 MRR / 销售徽章，或具备可核实自然流量规模。只有具备交易代理或持续营收证据时，M 轴才评为 `HIGH`。
   - **新晋赢家标记（`PROVEN_NEW_ENTRANT`）**：当探测到注册/上线不满 6 个月的新独立域名闯入 Top 5 且具备 `COMMERCIAL_TRACTION` 时，卡片高亮标记，提供最直观的“反向克隆”验证。
4. **信息流回答做不做（产出健康区间与特征补偿）**
   - **Verdict 健康产出区间**：目标每周稳定输出 1–5 条 `BUILD_NOW` 或 `EARLY_BET`，严防“0 产出导致漏斗干涸”。产出低于下限只触发人工复核，**不得为凑产出自动调阈值**；新阈值必须先经 SHADOW 对比（05 §7.2）。「每周 1–5 条」（新增数）与 §5.7 的「≤ 5%」（存量占比）分开监控。
   - **复合得分与特征补偿**：摒弃纯布尔硬截断。当需求极强爆发（D=HIGH）且竞争极度空虚（W=HIGH）时，若具备基础商业信号（M=MEDIUM），且该 MEDIUM **至少含一条 `COMMERCIAL_TRACTION` 或定价持续 ≥ 90 天**，通过补偿机制即可评为 `BUILD_NOW`（标明 `RULE_BUILD_NOW_COMPENSATED`）。只有多站静态 `PRICING_DECORATION` 的 MEDIUM 最多到 `EARLY_BET`（v2.2，Q1）。
   - **激活 `EARLY_BET`**：定位为“先上车后补票”。门槛为 D=HIGH 且 W ≥ MEDIUM（或快车道脉冲下 D ≥ MEDIUM 且 W=HIGH），即使商业未验证亦允许发布，为 Builder 留出抢跑窗口。
5. **动作闭环与防公地悲剧（原子绑定 + 形态锁槽 + 承诺质押 + 处女地买断）**
   - **按形态分流锁槽（Archetype-Level Slotting）**：每条机会按推荐形态切分独立槽位（如 `[Web 工具站 ×2]`、`[Chrome 插件 ×2]`、`[PSEO 目录 ×2]`），总认领上限默认 3–6 人，引导订阅者差异化切入，避免同质化内卷。
   - **认领与导出原子强绑定（Atomic Claim & Export）**：**“不点 GO 锁槽，绝不允许导出 AI 点火包”**。用户必须选择某一具体形态点击「做」（GO），系统在扣减 **1 次月度立项导出配额**的同时，占用 **1 个活跃 GO 槽位**并解锁该形态专属的 AI 点火包下载，杜绝“白拿点火包不占槽”的规避行为。
   - **防恶意占坑机制（Commitment Stake）**：每位 Pro 用户同时最多持有 **2 个 Active 状态的 GO 槽位**。「Active」指**质押尚未核验通过**的 GO；核验通过后不再计入这条上限，但它在机会上占用的形态槽位不变（v2.2，Q15）。点击 GO 后，须在**质押窗口**内提交上线凭证。窗口按所选形态的执行规模：S **7 天**、M **14 天**、L **21 天**（v2.2，Q5）。支持 3 类凭证：① 独立域名 URL；② Chrome Web Store / Shopify App 等应用商店详情页 URL；③ 公开的 GitHub Release 或产品着陆页 URL（含应用商店审核期间的预发布着陆页）。系统通过轻量 HTTP 探针校验页面 `<title>`/`<meta>` 相关性，逾期未提交或校验不通过则自动释放槽位返还公共池。已扣减的月度导出配额不予退还，作为恶意占坑惩罚；**每位用户首次逾期退还 1 次配额**，之后不退。
   - **满额锁定与处女地独占买断（Stealth Lock）**：所有形态槽位满额后标记为 `CROWDED_LOCKED`，停止新推荐并对 W 轴施加负反馈。同时提供高溢价增值服务：**「独占买断（Exclusive Buyout）」**——**仅当该机会的 `已认领槽位数 == 0`（无人染指的纯处女地状态）时开放买断按钮**（一旦有任一用户点了 GO，买断按钮立即置灰不可用）。买断后该机会从全网 Feed 中彻底隐藏下架 60 天，由买断者一人独享窗口期。
     - **`Σclaimed == 0` 约束的是下单那一刻，不是之后**。买断者本人**保留在这条机会上 GO 的权利**：他买的是"一人独享窗口期"，若连立项都不允许，这个商品就什么也没交付。因此买断之后 `Σclaimed` 会从 0 变为 1，而 60 天打码继续到 `unlock_at`——被打码的是**账本投影**，不是买断者自己的项目（§1.7 第 7 条）。
     - **买断是"先占位、后付款"**：托管结账页面意味着付款完成时锁还不存在，若等到付款才建锁，付款与建锁之间别人可以点 GO 占槽，于是钱已收、无物可交。所以下单即建锁（`provider_payment_id` 为空表示尚未付款），锁同样立即生效、机会同样立即从全网隐藏；待付窗口（默认 **15 分钟**）一过而钱仍未到，占位自动作废、机会重新开放。同一规范化身份或同一设备 30 天内累计 2 次未付作废后，取消其买断下单资格，防止多账号轮流用待付窗口免费遮蔽机会（v2.2，Q8）。完整语义与"同一用户同时至多一笔待付占位"这条防滥用闸见 10 §4.5b 与 03 §17 I13/I15。
6. **付费物与免费层钩子（防背刺的准实时精选 + 终身 1 次半遮罩初筛）**
   - **Free**：公开战绩大盘、**每周 1 条准实时精选机会卡片（仅展示刚刚被 Pro 用户认领满额触发 `CROWDED_LOCKED` 或刚进入 `WINDOW_CLOSING` 的真实案例，严禁将仍有空余槽位的黄金 `BUILD_NOW` 暴露给免费大盘以防背刺付费用户；7 天内没有新案例时，回退展示最近一条满足同一资格的历史案例并标注「历史案例」，v2.2 Q10）**、实时候选异动池（Watching Queue）只读浏览、每月 1 份历史案例报告预览（不可导出）、**终身仅 1 次（1 Lifetime Quota）自定义词「即时静态初筛（半遮罩展示）」**。Free 不能点 GO，不支持告警。
   - **Pro（支持季度/年度 Builder Pass）**：全量实时信息流、完整详情、认领槽位特权、**每月 5 次深度立项锁槽与 AI 点火包导出**（未用完额度结转下一期，结转后余额上限 10 次，v2.2 Q3）、每月 15 次自定义词初筛与雷达追踪（不结转）、Watchlist 邮件告警（Webhook 在 Gate 1 之后交付，F9）、Project 自动排名追踪。
7. **可证伪战绩大盘与加密延迟解密（Sealed Ledger）**
   - Merkle 树作为底层后台不可篡改的技术审计存证，前台底栏仅留校验入口；
   - **统计口径（v2.2，Q11）**：汇总统计纳入**全部**已发布 Episode，包括无人认领的失误，不得只统计已满额或已关窗的机会；逐行明细在「失去抢跑价值」「完成 T+90 评估」「买断打码期满」三者先到时公开；全部统计从第一条管线写入的可复验账本行（v2 纪元）起算，种子数据不计入；
   - 前台主打 **公开 Cohort 战绩大盘（Hit Rate & Accuracy Matrix）** 与事后复盘：系统自动前向追踪 T+30/60/90 天主词搜索量走势、SERP 新独立站存活情况及平台已立项域名的自然排名爬升；
   - **买断项目延迟解密规则**：被用户通过 `Stealth Lock` 独占买断的机会，照常写入底层 Merkle 账本并计入整体胜率统计；但在 60 天独占保护期内，前台战绩大盘将其关键词与实体打码展示为 `[Stealth Locked #ID]`，待 60 天保护期满后自动解密公开具体词根。

## 2. 产品原则

| ID | 原则 |
|----|------|
| P1 | **证据先于分数**：任何结论可追到 `evidence_id` + `snapshot_id` |
| P2 | **诚实标签**：证据类别永不混算；“数据不足”不等于“低” |
| P3 | **决策与点火优先**：每个界面回答“做 / 不做 / 怎么用 AI 今晚开工”，而不是堆砌图表 |
| P4 | **出货导向**：产品的成功以用户 7 天上线核验与 30 天排名爬升衡量，不以页面浏览量衡量 |
| P5 | **时间是资产**：快照不可变（含采集时冻结的分类标签）、账本只追加；越早采集越有价值 |
| P6 | **管理自己的拥挤效应**：同一个窗口不能无限卖给所有人，必须保护抢跑者与买断者的 Alpha |
| P7 | **100% 可重算**：分数与结论由确定性规则和版本化配置基于已冻结快照计算；重算时绝不重新调用 LLM |

## 3. 成功标准

### 3.1 北极星指标
**Verified Active Projects / Month**：过去 30 天内，从机会点击 GO、在**质押窗口内**通过上线凭证真实性核验，且由系统 SERP 管线持续追踪排名演进的项目数（无需强制绑定用户 GSC）。

### 3.2 可证伪假设
| ID | 假设 | 验证方式 | 初始通过线 |
|----|------|----------|-----------|
| H1 | “autocomplete 新增 + SERP 偏弱 + 增长”的早期信号能预测搜索市场的形成 | 预测账本 T+30/60/90。结果事件必须**独立于 D 轴输入**：用第三方词量或 Trends 走势定义的外部需求形成（`ev-1.1`，06 §7），不得用簇扩张 / 新增 query 自证。对照基线：同池随机；Google Trends 上升榜（**必备**） | Top-decile 机会的 60 天外部需求形成事件率 ≥ 基线 3×。Gate 0 以 T+30 与代理回测判定，T+60 在 Gate 1 前复核 |
| H2 | 有 observed 商业证据（尤指新晋赢家）的机会更值得做 | Design partner 结果 + SERP 排名追踪 | 定性成立，样本持续积累 |
| H3 | Builder 愿意为“确定性决策 + AI 建站点火包 + 槽位保护”付费 | 预售访谈与付费转化 | ≥ 20 访谈，≥ 8 人预付或签意向 |
| H4 | 机会研究报告与 AI 点火包显著提升 Builder 的立项信心与极速出货率 | Design partner 跟踪 | GO 后**质押窗口内（S 7 / M 14 / L 21 天）上线凭证核验通过率 ≥ 40%**，且 **30 天内进入 SERP Top 100 比例 ≥ 30%** |

任一假设不过线：先修假设，不增加功能。

### 3.3 指标体系
- **漏斗**：Feed / 即时初筛钩子 → Detail → GO（原子锁槽并导出 AI 点火包） → 质押窗口内上线凭证核验通过 → 30 天内 SERP Top 100 排名入榜 → 季度留存 / 额度复购。
- **质量**：
  - Market-formation precision（自动、代理指标）：已发布 verdict 的 T+30/60/90 市场形成事件命中率。
  - Builder-outcome precision（SERP 真实排名追踪 + 可选 GSC）：追踪已核验项目在 30/60 天内进入 Top 100 / Top 30 / Top 10 的比例。
  - 机会报告与点火包 rubric 通过率。
  - PASS 理由分布与 7 天槽位逾期释放率。
- **获客**：landing（官方 Demo 热词演练） → 注册激活唯一 1 次初筛 → 触发半遮罩付费墙 → Pro 转化；公开战绩页与历史案例引流。

### 3.4 反指标与护栏
- **反指标**（禁止作为目标）：机会浏览数、生成页面数、纯流量、被羊毛党刷走的免费初筛次数。
- **护栏**：单机会月数据成本；整体毛利率（目标 ≥ 70%）；误报申诉数；告警退订率。

## 4. 用户旅程

### 4.1 首次使用（双路径 Aha Moment）
1. **配置偏好**：回答至多 4 个问题（见 F12）→ 进入个性化 Feed → **3 分钟内浏览准实时精选案例与完整证据链**，或点击 3 个预置官方 Demo 词零成本体验完整报告与点火包样本。
2. **自带灵感求证（转化钩子）**：用户输入自己的私密灵感词 → 消耗账号**终身唯一 1 次**免费实时初筛额度 → 5 秒内获得《静态竞争与变现初筛卡》（可见核心结论，但具体弱结果 URL、赚钱竞品域名与长尾词表被打码模糊）→ 引导升级 Pro 解锁底牌并开启 7 天时序脉冲雷达。

### 4.2 立项与点火循环
Feed → Detail → Compare（可选）→ 选择细分形态点击 GO（原子操作：锁槽 + 扣配额 + 解锁导出 **AI 建站点火包**） → 喂给 Cursor 开发上线 → **质押窗口内（S 7 / M 14 / L 21 天）回填上线凭证（域名 / 插件商店链接 / GitHub 落地页）完成质押核验** → 系统每周自动追踪 SERP 排名爬升。

### 4.3 告警循环
Watch 的机会或自定义追踪词发生变化（7天脉冲确认晋升 `BUILD_NOW`、窗口关闭、Kill criteria 命中、立项域名进入 Top 20）→ 通知 → 回到 Detail 决策。

## 5. 核心概念与决策模型

### 5.1 核心对象
| 对象 | 说明 |
|------|------|
| Opportunity | 一个实体 + query cluster + `market_country` + `research_language` |
| Evidence | 带类别、来源、时间戳的最小事实单元 |
| Snapshot | SERP（默认 Top 10；映射到已核验 Project 的 query 每周一次 Top 100，见 F1 第 1 条） / autocomplete / 商业信号的不可变快照（**含入库时一次性生成并永久冻结的分类元数据**） |
| Verdict | 某个 `scoring_config` 版本在某时点对 Opportunity 的判断 |
| Prediction Ledger | 所有已发布 Verdict 的 append-only 记录（支持 Stealth Lock 项目的 60 天延迟解密展示） |
| Project | 用户认领槽位（GO）后创建的实际项目，绑定上线凭证 URL 与认领形态 |

### 5.2 三个互相独立的语言与地域概念
| 概念 | 含义 |
|------|------|
| `ui_locale` | 界面与系统消息语言（支持 `zh-CN` 与 `en-US`） |
| `research_language` | 关键词、搜索需求、内容分析的目标语言（首发固定 `en-US`） |
| `market_country` | SERP、趋势、商业化与竞争分析对应的国家 / 地区（首发固定 `US`） |

任何一个都不得隐式覆盖另一个。

### 5.3 `first_observed`
时间字段统一为 **首次被本系统观测到（`first_observed`）**，不等同于“世界上首次出现”。界面使用“首次观测”字样；Methodology 页披露观测起始日期与覆盖范围。

### 5.4 证据类别
| 类别 | 含义 | 对商业验证（M 轴）的作用 |
|------|------|--------------------------|
| `observed` | 系统直接观测（定价页、checkout、公开评论/安装计数器、平台披露的销售数据） | 可参与全部评级 |
| `self_reported` | 当事人自报，必须显式标注 | 可参与评级，但不能单独达到 High |
| `third_party_estimate` | 第三方估算，必须显式标注 | 仅展示；无 observed 佐证时权重为 0 |
| `inferred` | 系统推断（如商业意图查询） | 仅可支撑 Low 与 Medium 之间的判断 |

**硬性规则**：仅检测到 Stripe / Paddle / 支付按钮（`PRICING_DECORATION`），只证明“存在变现基础设施”，不等于有真实收入。矛盾证据必须保留并展示，不得被覆盖。

### 5.5 三轴与证据置信度
每轴分档：`High` / `Medium` / `Low` / `Insufficient`（数据不足）。另有 **Evidence Confidence**：High / Medium / Low，由独立来源数、新鲜度、observed 占比决定。

| 轴 | 回答的问题 | 主要输入 |
|----|-----------|----------|
| **D — Demand Formation** | 需求是否在形成 | autocomplete 新增与增长（7/30/90 天）、query cluster 扩展、跨源关注触发 |
| **M — Commercial Proof** | 是否已有钱在流动 | 商业信号引擎（F7），区分装饰性定价与真实交易代理 |
| **W — Entry Window** | 窗口是否还开着 | SERP 弱度、竞争变化率、权威新进入者、平台内认领槽位拥挤度（拥挤度只影响 W 展示值与 `CROWDED_LOCKED`，不参与窗口关闭的降档判定，见 §1.7 第 2 条） |

### 5.6 M 轴分档规则（初始值，严防僵尸站越级）
- **High**：≥ 2 个独立域名存在 observed 定价 / checkout，且满足以下之一：① 具备 `COMMERCIAL_TRACTION`（如插件安装/评论正增长、公开销售徽章、可核实流量规模或标注的 self-reported 营收）；② 定价 / checkout 在 ≥ 90 天的快照中持续存在，**且在此期间站点的自然搜索排名、评论计数或外链指标存在非零正增长（严格排除无人问津的僵尸定价站）**。
- **Medium**：≥ 2 个独立域名有 observed 定价 / checkout，但尚无交易代理证据或增长痕迹（多站静态 `PRICING_DECORATION`）；或存在 observed 的类目 / 类比验证。
- **Low**：仅有商业意图查询，或仅单个独立站检测到支付 provider。
- **Insufficient**：采样不足（且超出 72 小时故障缓存期）。
- 强负面信号（如竞品下架付费层、公开退款潮）可降档。

### 5.7 Verdict（按顺序评估，首个命中即生效）
| Verdict | 条件（初始值） |
|---------|---------------|
| **BUILD NOW** | (D ≥ Medium ∧ M = High ∧ W ≥ Medium ∧ Confidence ≥ Medium) 或触发高需求高空窗补偿规则 `RULE_BUILD_NOW_COMPENSATED` (D = High ∧ W = High ∧ M = Medium，且 M 含 `COMMERCIAL_TRACTION` 或定价持续 ≥ 90 天) |
| **EARLY BET** | (D = High ∧ W ≥ Medium) 或快车道脉冲下 (D ≥ Medium ∧ W = High)，且 M ∈ {Low, Medium, Insufficient}；界面明确标注“商业未验证，抢跑窗口” |
| **WINDOW CLOSING** | 此前已发布的裁决为 BUILD NOW / EARLY BET，且市场 W（不含认领拥挤项）在 14 天内下降 ≥ 1 档，或平台内所有形态认领槽位已满（`CROWDED_LOCKED`） |
| **WATCH** | D ≥ Medium，且不满足以上任一条件 |
| **PASS** | D = Low，或 M 出现强负面信号，或 W = Low |

目标稀缺性：BUILD NOW 占已发布（`status = TRACKED` 且通过 §1.7 发布资格）机会的 ≤ 5%，且保持每周 1–5 条的健康产出区间。

### 5.8 机会生命周期（市场状态）
`FORMING` → `EARLY_WINDOW` → `CONTESTED` → `MATURE` → `DEAD`

| 转换 | 规则（初始值，配置化） |
|------|-----------------------|
| FORMING → EARLY_WINDOW | D ≥ Medium ∧ W ≥ Medium |
| EARLY_WINDOW → CONTESTED | W 下降 ≥ 1 档，或 Top10 新增 ≥ N 个 specialist / 权威竞品，或平台认领槽位满额 |
| CONTESTED → MATURE | 竞争结构稳定 ≥ 60 天，且 velocity 趋平 |
| 任意 → DEAD | 需求指标下降并持续 ≥ 60 天 |

### 5.9 拥挤度与槽位透明度（Crowding & Slotting）
直接透明展示当前机会各 Build Archetype 的剩余可认领槽位数（例如：`Web 工具站：剩余 1/2 槽位`，`Chrome 插件：剩余 2/2 槽位`），不再使用 k-anonymity 隐藏，以此强化真实稀缺感与紧迫感（保护认领者项目隐私，仅展示槽位占用状态）。

### F1 信号管线与预测账本（低成本、防限流与高可用架构）
**目的**：用极低的边际数据成本构建随时间积累的观测数据壁垒，严防并发限流与偶发爬虫故障抖动。

**核心工程约束（低成本与高可用铁律）**
1. **SERP 深度分层与一鱼多吃（v2.2，Q14）**：Google 自 2025 年 9 月停用 `num=100`，取 Top 100 需按 10 条一页计费的 10 次请求。因此默认每次只采 **Top 10**，用于计算 F6（SERP Weakness）；只对**映射到已核验 Project 的 query** 每周采一次 **Top 100**，同一份快照同时更新 W 轴与第 11–100 名的项目排名匹配（F10）。**严禁为追踪用户项目在这次采集之外单独发起重复的关键词 SERP 请求**（ADR-022）。
2. **双通道削峰隔离（Fast Lane vs. Slow Lane）**：
   - **Fast Lane（实时通道）**：仅服务于用户在前端主动触发的「即时初筛」。通过 Postgres 全局令牌桶（`rate_limit_buckets`）严格限制全局最大并发（如 ≤ 5 req/s），且强制经过 **7 天全局去重**——7 天内任何用户查过的相同词，直接复用已落库的 `serp_snapshots` 快照毫秒级返回，API 成本为 0（不引入 Redis，ADR-017）。
   - **Slow Lane（批量巡检通道）**：服务于每日 Opportunity 例行观测与每周战绩回测。100% 采用第三方 SERP 服务商的低价异步队列（Standard / Async Queue API），并将全天任务通过 pg-boss 队列（ADR-003）**均匀打散在 24 小时（1,440 分钟）窗口内匀速执行**，彻底杜绝整点并发尖峰与 429 限流。
3. **采集故障 72 小时优雅降级（Stale-While-Revalidate）**：
   - 单源 Collector 相互隔离。当某条轴的采集器因目标站点改版或代理超时偶发失败时，**默认沿用过去 72 小时内最后一次成功的 Snapshot 分档（界面标注 `STALE_DATA`），不立即将该轴重置为 `INSUFFICIENT`，也不触发错误的 Verdict 降级告警**；仅当连续失败超过 72 小时，才正式降级为 `INSUFFICIENT`。
4. **预测与成本账本**：所有 Snapshot 不可变；每日 Verdict 以 append-only 写入；每次采集记录精确成本并按源/机会/用户汇总。

**验收**：任意历史日期的 Verdict 可 100% 复现（Gate 0 做一次 v2 纪元全量重算）；500 活跃用户规模下，月度新增边际 SERP API 成本控制在 $20 以内（按页计费口径，由 04 §6.3 的 Gate 0 成本表反推验证；反推不成立时 Gate 0 不通过）。

### F2 机会引擎（确定性重算与 LLM 快照冻结）
**需求**
- **快照标签入库冻结（消除 LLM 重算不确定性）**：LLM 仅允许在数据采集入库阶段（Ingestion Phase）参与实体归并候选与 SERP 结果类型分类（specialist / UGC / official / weak），其输出的分类标签必须通过 schema 校验并**作为不可变 Snapshot 的静态字段永久冻结落库**。
- **100% 确定性评分引擎**：F2 评分引擎在计算或历史重算（Re-scoring）三轴分档与 Verdict 时，**仅读取 Snapshot 中已冻结的静态分类标签与确定性数值，重算过程严禁再次调用 LLM**，从而确保同一 Snapshot 集合 + 同一 `scoring_config` 版本在任何时间重跑均 100% 得出完全一致的分数与结论。
- 自动识别并标记 `PROVEN_NEW_ENTRANT`（上线 < 6 个月、进入 Top 5 且具备真实交易信号的独立站）。

### F3 Opportunity Feed 与「即时初筛沙盒」
**需求**
1. **主信息流**：只列出通过发布资格且未被独占买断隐藏的机会。默认 Tab 为 `BUILD NOW`；另有 `EARLY BET` / `WATCH 变化` / `WINDOW CLOSING` 及只读的「实时候选异动池（Watching Queue）」。
2. **两阶段自定义词初筛沙盒（替代纯等待）**：
   - 搜索框下方预置 **3 个官方示例热词（Demo Queries）**，点击直接零成本读取缓存展示完整初筛效果。
   - 用户输入自定义词时，弹窗确认消耗额度（Free 用户提示消耗**终身唯一 1 次**免费额度；Pro 用户扣除月度初筛配额）。
   - **第 1 阶段（5 秒即时静态初筛卡）**：调用 Fast Lane 实时探针，当场返回静态 SERP 弱结果数与独立站收款探针结论。
     - **Free 用户半遮罩展示（Blurred Reveal）**：清晰展示“发现 N 个弱结果 + M 个收钱独立站 + 静态切入难度”以制造 Aha Moment；但对**具体弱结果 URL、收钱竞品域名、15 个高意图扩展长尾词进行高斯模糊打码**，引导升级 Pro 解锁。
   - **第 2 阶段（7 天动态脉冲雷达）**：Pro 用户可将初筛通过的词一键加入 `CANDIDATE` 快车道高频监测，一旦 7 天内确认需求脉冲斜率达标，第一时间以邮件与站内通知推送抢跑通知（Webhook 在 Gate 1 之后交付，F9）。

### F4 Opportunity Detail
**首屏（无需滚动）**：Verdict、D-M-W 分档、Confidence、`PROVEN_NEW_ENTRANT` 徽章（如有）、研究市场（en-US）、一句 Why Now、各形态剩余认领槽位、主操作按钮组：
- **「选择形态并立项（GO & Export Launch Kit）」**：原子操作按钮，点击后选择具体 Build Archetype，占用 1 个活跃槽位、扣减 1 次月度导出配额，并立即解锁下载该形态专属的 AI 点火包与研究报告。
- **「独占买断（Stealth Lock）」**：仅当 `已认领槽位 == 0` 时高亮可用；一旦有任一槽位被认领，该按钮立即置灰并提示“已有开发者切入，无法独占买断”。
- 辅助操作：PASS（需选理由） / Watch。

**正文按决策顺序**：
1. Why Now 与跨源动量
2. Search Formation：新增 query、intent cluster、7/30/90 天变化、query graph
3. SERP Intelligence（F6）：具体弱结果列表与新晋赢家解剖
4. Commercial Proof（F7）：含 **What this proves / What this does not prove** 及竞品定价锚点
5. What to Build & Slotting：推荐 Build Archetype（≤ 3），展示各形态剩余槽位、MVP 范围、技术复杂度、执行规模（S/M/L）
6. Monetization 路线：Primary / Secondary / Not recommended
7. **Kill criteria**：≥ 2 条明确的止损放弃条件，可一键转为 Watch 告警
8. **Pre-mortem**：最可能的失败原因，引用证据
9. 评分分解：由确定性规则渲染

### F5 Compare
- Web 支持 2–3 个机会并排对比：Verdict、三轴、新晋赢家数量、各形态剩余槽位、是否支持独占买断、执行规模、Kill criteria 状态。

### F6 SERP Intelligence
- 每个被追踪 query 保存 Top 10 快照（映射到已核验 Project 的 query 每周一次 Top 100，F1 第 1 条）；针对 Top 10 解析结果类型（入库时冻结）、域名年龄/权威分类、相关性、新鲜度，以及 specialist / UGC / official / weak 结果数量。
- **列出具体的弱结果证据**（例如“第 3 位是 2022 年无人维护的 Reddit 帖”），并高亮近 6 个月新闯入 Top 10 的独立站域名。

### F7 Commercial Signal Engine
- 严格区分 `PRICING_DECORATION`（仅检测到支付按钮/定价页，无增长痕迹）与 `COMMERCIAL_TRACTION`（评论增长、销售计数、可验证流量）。
- 支持 direct / category / analog 三级验证，保留历史商业快照与矛盾证据。
- 构造测试集覆盖“仅检测到支付 provider 的僵尸站”“存在矛盾证据”“估算无佐证”三类情形，M 轴均不得越级为 High。

### F8 机会研究报告与 AI 建站点火包 (Opportunity Report & Launch Kit)
**目的**：消除“看完报告还要自己写 PRD 和整理词表”的摩擦，让 Builder 复制粘贴进 Cursor / Claude Code 即可当天开工。**（须通过点击 GO 绑定形态槽位后方可导出）**。

**交付物一：权威商业决策报告（面向人阅读，6 个板块）**
1. Executive Summary、2. Demand Intelligence、3. Commercial Evidence、4. SERP Weakness Audit、5. Strategic Archetype、6. Risk & Kill Criteria。（90% 确定性装配，LLM 仅生成 ≤ 500 字摘要，支持 Markdown / PDF / JSON 导出）。

**交付物二：Vibe Coding AI 建站点火包（按所选 Build Archetype 动态装配）**
1. **`CLAUDE.md` / `.cursorrules` 工程规范文件**：基于该机会的 SERP 竞品弱点与用户认领的具体形态（如 Web 工具站或 Chrome 插件），自动装配项目技术栈建议、核心功能 MVP 边界、UI/UX 避坑指南与完整开发 Prompt。
2. **Programmatic SEO 路由与种子词表（CSV / JSON）**：将该机会下的 query cluster 自动转化为可直接导入 Next.js / Astro 的动态路由数据结构（包含 `slug`、目标关键词、搜索意图分类、建议 `<title>`、`<h1>` 与 Meta Description 模板）。
3. **高转化 Landing Page 骨架文案（Markdown）**：基于 F7 已验证的竞品痛点与定价区间，生成经过商业证据锚定的 Hero Section、痛点对比矩阵、FAQ（覆盖长尾问题）及 Pricing Tier 建议文案。

### F9 Watchlist 与 Alerts
- 触发器：Verdict 变化（排除 `STALE_DATA` 缓存期）、自定义初筛词 7 天脉冲确认、WINDOW CLOSING、槽位仅剩最后 1 个、**Kill criteria 命中**、已立项凭证在 SERP 出现显著排名跃升（如进入 Top 100 / Top 30 / Top 10）。
- 渠道：首发只交付 Email（含站内通知）；通用 Webhook（内置 Slack / Discord / Telegram 模板）在 Gate 1 之后交付（v2.2，Q4）。首发触发器即以上 6 条，不额外扩展。

### F10 Project 多凭证质押核验与无感 SERP Outcome Tracking
**目的**：解决出海站长“闷声发财不愿授权 GSC”的信任摩擦，兼容插件/SaaS 形态，同时严防恶意占坑。

**需求**
- **认领质押与多凭证轻量核验**：用户点击 GO 占用某个形态槽位并导出点火包后，须在**质押窗口**内（S 7 天 / M 14 天 / L 21 天，§1.7 第 5 条）回填已上线的项目凭证 URL。系统支持 **3 类有效上线凭证**：
  1. **独立域名 URL**（适用于 Web 工具站 / PSEO 目录站）；
  2. **官方应用商店详情页 URL**（适用于 Chrome Web Store 插件、Shopify App 等，支持提交审核通过后的商店链接或预发布落地页）；
  3. **公开的产品着陆页 / GitHub Release URL**（适用于 API / CLI / 桌面工具）。
  系统使用**零成本的服务端轻量 HTTP 探针（`fetch`）**访问该 URL，提取 `<title>`、`<h1>` 与 `<meta>` 校验是否与该机会主题相关。窗口内未提交或校验不通过，自动撤销 GO 状态并释放槽位（已扣减的导出配额不退还；每位用户首次逾期退还 1 次）。
- **零成本 SERP 排名无感追踪（核心默认项）**：系统每周对映射到已核验 Project 的 query 执行一次 F1 的 Top 100 采集（F1 第 1 条），在内存中匹配该 Project 的域名或商店链接，生成该项目的自然排名爬升曲线（如：未入榜 → 第 68 名 → 第 12 名），直接作为计算 Builder-outcome precision（30 天 Top 100 入榜率）与公开战绩大盘（匿名化展示）的客观依据。
- **GSC 只读 OAuth（降级为可选增强项）**：仅供愿意深度复盘精细曝光/点击数据的用户自愿连接，不做强制要求。

### F12 Onboarding 与国际化
- **Onboarding**：至多 4 问——Build 偏好、目标市场（默认固定 en-US）、感兴趣领域（可选）、**时间预算**（周末 / 两周 / 一个月，映射到执行规模 S/M/L）。
- **国际化**：UI、报告与 AI 点火包说明支持 `zh-CN` 与 `en-US`；但生成的 PSEO 词表、Landing Page 文案与原始关键词严格保持目标研究市场语言（`en-US`）。

### F14 管理后台与防白嫖滥用检测（首发最小集）

## 7. 公开获客层

### 7.1 原则
- **准实时样本防背刺 + 公开战绩验证**。彻底废除旧版“45 天延迟公开”规则；向免费用户每周开放 1 条**刚刚满额锁定（`CROWDED_LOCKED`）或刚进入 `WINDOW_CLOSING` 的准实时 `BUILD_NOW` 样本**与只读异动池——既让免费用户直观感受到实时情报的震撼质量，又确保尚有空余槽位的黄金机会 100% 留给付费 Pro 用户抢跑。
- 公开页由 public projection 生成，不手工复制分数或证据。

### 7.2 页面范围（首发）
- **Landing**：展示真实的已发布机会卡 + **3 个可零成本点击体验的官方 Demo 初筛热词**。主按钮引导进入信息流或注册激活唯一 1 次私密词初筛。
- **Track Record（公开战绩大盘与延迟解密）**：展示系统自动前向追踪的 T+30/60/90 天结果、市场形成命中率、平台已立项项目的匿名排名爬升率（30 天 Top 100 / Top 30 入榜率）、以及公开的**失误复盘（Misses & Post-mortems）**。处于 60 天独占买断期内的项目在账本中展示为 `[Stealth Locked #ID]`，期满自动解密公开。底栏附密码学 Merkle 根校验入口。
- **公开历史案例拆解页**：展示已进入 `CONTESTED` 或 `CROWDED_LOCKED` 阶段的历史机会完整复盘。
- Pricing、Methodology、Data Sources、Login / Signup。

## 8. 商业模式、防流失包装与单位经济

### 8.1 套餐与防流失包装（对抗“建站开发期退订”）
独立开发者选定项目后会有 2–4 周的开发冷启动期，传统高频查词配额（如每月 30 份报告）会导致极高的次月退订率。因此采用**“认领导出原子绑定 + 跨月累计（Rollover） + 季度 Pass + 处女地独占买断”**设计：

| 权益维度 | Free（体验与防白嫖层） | Pro（独立 Builder 主力层） | Stealth Buyout（单次增值买断） |
|---------|----------------------|--------------------------|------------------------------|
| **实时机会流 (Feed)** | 每周 1 条刚满额锁定的准实时 `BUILD_NOW` 案例 + 候选池只读 | 全量实时 `BUILD_NOW` / `EARLY_BET` 空槽可认领信息流 | — |
| **自定义词即时初筛** | **终身仅 1 次**（结果半遮罩打码，需 GitHub/Google 登录） | **每月 15 次**（全量解锁底牌 + 可转 7 天脉冲雷达） | — |
| **立项锁槽与 AI 点火包导出** | 每月 1 份历史报告在线预览（无点火包、不可导出） | **每月 5 次原子立项（锁槽 + 导出 AI 点火包）**（未用完额度结转下一期，结转后余额上限 10 次）；同时最多持有 **2 个质押未核验的活跃 GO** | — |
| **处女地独占下架特权** | 不支持 | 可对 `已认领槽位 == 0` 的机会发起买断 | **单次付费（如 $199–$299/次）**：将该未染指机会从全网隐藏下架 60 天（账本打码封印），一人独享窗口 |
| **自动化追踪与告警** | 不支持 | 邮件与站内告警（Webhook 在 Gate 1 之后）+ 立项凭证每周 SERP Top 100 自动追踪 | 包含全套追踪 |

- **季度 Builder Pass（主推档位）与对赌兜底承诺（De-risking Guarantee）**：
  - 主推季度订阅（90 天恰好覆盖“立项 → Vibe Coding 7 天上线 → 30/60 天 SEO 排名爬升”的完整周期）。
  - **兜底承诺（v2.2，Q7）**：只保留一条可计量的触发条件：连续 2 周全平台合格 `BUILD_NOW` + `EARLY_BET` 为 0 时，自动延长订阅 7 天。补偿只给时长或额度，不退现金。触发条件不由团队可调的阈值决定。
- **供给约束（v2.2，Q6）**：每周 1–5 条 × 每条 ≤ 6 槽，全平台每月约 120 个槽位。Phase 1 期间 Pro 席位上限 30（与 Gate 1 的 design partner 规模一致）；Gate 1 后按实测的月均可认领槽位数重算配额与席位。
- **Founding Pro Lifetime（v2.2，Q12）**：一次性付款，复用 Pro 权益与月度配额，**限额 50 席**，售罄即止；不承诺无限报告、无限抓取或未来高成本功能。

### 8.2 单位经济约束（Unit Economics）
- 目标毛利率 **≥ 70%**。
- 依托 F1 的“SERP 深度分层”、“7 天全局去重”与“24 小时异步低价队列”，将单付费用户每月产生的边际 API 采集成本严格控制在 **$1.00 以内**。

## 9. 非功能需求与数据治理

### 9.1 质量与确定性
- 所有推荐可解释；所有 Verdict 基于入库冻结的 Snapshot 标签 100% 确定性可重算；所有历史状态可回放。
- LLM 输出必须经 schema 校验，且事实性内容必须引用 `evidence_id`；AI 点火包中的硬数据（搜索动量、竞品价格、长尾词表）100% 由确定性模板注入，严禁 LLM 自由编造。

### 9.2 数据源合规与隐私保护
- 每个数据源须登记：获取方式、ToS 风险等级、单位成本、72h 降级方案。
- 用户提交的 Project 上线凭证 URL 默认严格保密（公开战绩大盘仅展示脱敏统计与排名跃升幅度，绝不暴露具体域名或商店链接，彻底打消站长顾虑）。

### 9.3 性能与可用性
- Feed / Detail p95 < 1.5s（缓存后）。
- 即时静态初筛（Fast Lane）：缓存命中 < 200ms；实时采集返回 < 8s（配前端扫描进度反馈）。
