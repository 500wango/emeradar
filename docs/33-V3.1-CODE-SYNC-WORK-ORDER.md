## 1. 怎么执行

- **一次只做一个阶段**。完成一个阶段、跑完验收、提交一次 commit，然后停下汇报，等下一阶段指令。不要在同一个会话里连做多个阶段。
- 每个阶段开始前先 `git status` 必须干净；有未提交改动先停下报告。
- 不要修改 `docs/`。文档是本次施工的输入，已冻结在 `59855a8`。
- 不要 `git push`、不要碰生产环境、不要对生产库执行迁移。只在本地仓库与本地数据库工作。
- 遇到与本文描述不符的代码（行号漂移、函数已改名、机制已部分拆除）：以实际代码为准继续，但在汇报里列出偏差；不要为了对上文档而改文档。

推荐启动方式（每次一个阶段）：


## 2. 权威口径（施工时必须遵守，不要重新推导）

### 2.1 裁决（01 §1.8 第 2 条、05 §5）

单值顺序，先命中先返回，不叠加：

```text
PASS → WINDOW_CLOSING → BUILD_NOW(标准) → BUILD_NOW(补偿) → EARLY_BET → WATCH
```

- `PASS`：D=Low、W=Low，或 M 出现强负面信号。
- `WINDOW_CLOSING`：此前**已发布**过 `BUILD_NOW` / `EARLY_BET`，且 W 在 14 天内下降 ≥1 档，当前 W ≥ Medium。
- `BUILD_NOW` 标准：`D≥Medium ∧ M=High ∧ W≥Medium ∧ Confidence≥Medium`。
- `BUILD_NOW` 补偿：`D=High ∧ W=High ∧ M=Medium`，且 M 至少含一条 `COMMERCIAL_TRACTION`，或定价/结账持续 ≥ 90 天。**仅凭 `independentDomainsCount ≥ 2`（多站静态 `PRICING_DECORATION`）不再满足补偿。**
- `EARLY_BET`：`D=High ∧ W≥Medium`，或快车道 `D≥Medium ∧ W=High`；M 可为 Low / Medium / Insufficient。
- 其余 `WATCH`；D=Insufficient 时带 `PARTIAL_DATA`。

### 2.2 W 轴（05 §3.3）

```text
pressure = min(100, 30·e_specialist_30d + 40·e_authoritative_30d + 3·volatility_30d)
W_score  = (0.60·serp_weakness + 0.25·(100 − pressure)) / 0.85
```

- `verified_product_count`、`top10_specialist_count`、`new_top10_entrants_30d` **不是 W 的输入**。它们只用于拥挤度透明度、生命周期（`EARLY_WINDOW → CONTESTED`）与 `CROWDING_SIGNAL` 告警。
- 拥挤度不得触发 `WINDOW_CLOSING`，不得限制 GO。
- `CROWDED_LOCKED` 已从 Verdict flags 中删除，任何代码路径都不得再产生它。

### 2.3 GO（01 §1.8 第 5 条、ADR-018、13 §4）

一次原子事务：

```text
reserve 1 次 atomic_go_export_monthly
→ 创建 Project 壳（credential_status='UNVERIFIED'，decision_id 唯一）
→ 解锁该裁决的 AI 点火包
```

- 配额：Pro 每月 3 次，未用完结转一期，结转后余额上限 6；Free 无 GO 权限。
- **没有槽位、没有容量上限、没有活跃 GO 上限、没有质押。** 并发 GO 各扣各的配额，不做任何"最后一个名额"检查。
- 同一用户对同一 `decision_id` 重复 GO：`409 ALREADY_GO`，配额不重复扣减。
- 凭证核验是 GO 之后的可选动作：无截止时间、失败不释放资源、不退还配额。状态 `UNVERIFIED` / `PENDING` / `VERIFIED_OWNER` / `REJECTED`。

### 2.4 公开资格（15 §3）

「已失去抢跑价值」任一满足即可公开：

1. 当前裁决 `WINDOW_CLOSING` 或 `PASS`；
2. 生命周期 `CONTESTED` / `MATURE` / `DEAD`；
3. 连续 14 天（含端点）不是 `BUILD_NOW` / `EARLY_BET`。

活跃的 `BUILD_NOW` / `EARLY_BET` **永不**公开；重新活跃时同一轮 S8 置回 `DRAFT` / 404。没有 45 天延迟、没有槽位满额旁路、没有买断打码。

### 2.5 告警（12 §2）

首发 6 条：`VERDICT_CHANGE`、`WINDOW_CLOSING`、`CROWDING_SIGNAL`、`KILL_CRITERIA`、`PROJECT_SERP_RANK_JUMP`、`CUSTOM_QUERY_PULSE_CONFIRMED`。

`SLOTS_LAST_ONE` 已删除，由 `CROWDING_SIGNAL` 取代：`crowding_daily.verified_product_count` 首次达到 3，或 `new_top10_entrants_30d` 较上次推送增加。只提示竞争加剧，不限制 GO。

## 4. 阶段 A — 评分层去拥挤度与裁决顺序

**目标**：让 `@emeradar/scoring` 的输出与 05 v3.1 完全一致；拥挤度退出 W。

### A1. 删除 crowding 对 W 的影响

- `packages/scoring/src/window.ts`：W 的计算不得再读取 `crowdingIndex`、`verified_product_count` 或任何槽位/认领计数；按 §2.2 的公式实现 `serp_weakness` 与 `pressure` 两项。
- 若当前存在「展示用 W（含拥挤）」与「市场 W（不含拥挤）」双输出：保留展示语义，但**账本与 `WINDOW_CLOSING` 只读不含拥挤的那一个**。
- `packages/scoring/src/types.ts`：`WindowFeatures` 中只服务于槽位/拥挤的字段要么删除，要么明确标注为不进 W 的展示输入。

### A2. 删除 `CROWDED_LOCKED`

- `packages/scoring/src/verdict.ts`、`types.ts`：删除常量、类型联合成员与所有产生分支。
- 全库 grep `CROWDED_LOCKED` 应为 0（文档除外）。

### A3. 补偿路径收紧

- `verdict.ts`：`M=Medium` 的补偿必须要求 `hasTransactionTraction` 或 `pricingPersistentDays ≥ 90`；删除 `independentDomainsCount ≥ 2` 单条件放行。
- 纯装饰性 MEDIUM 最多落到 `EARLY_BET`。

### A4. 裁决单值顺序

- 确认 `PASS → WINDOW_CLOSING → BUILD_NOW → BUILD_NOW(compensated) → EARLY_BET → WATCH` 是返回单一值的短路逻辑，不是多 flag 叠加。
- `WINDOW_CLOSING` 必须同时满足：前置已发布裁决 ∈ {`BUILD_NOW`,`EARLY_BET`}、降档发生在 14 天内、当前 W ≥ Medium。
- 快车道（`FAST_TRACK`）分支保持 7 天门槛，不得回退到 14 天。

### A5. 版本与测试

- 评分规则变化必须进新的 `scoring_config` 版本；不得直接改已生效版本的行为（ACTIVE 只前向生效）。仓库当前版本号以代码为准，改前先读 `SCORING_CONFIG_VERSION`。
- 更新 `packages/scoring/test/scoring.test.ts`：新增「拥挤度不进入 W」「纯装饰性 MEDIUM 最多 EARLY_BET」「`CROWDED_LOCKED` 不再产生」三条 Golden。
- 不得删除既有断言来让测试变绿；口径变了就改期望值并在 commit message 说明。

## 11. 已知陷阱

| 现象 | 原因 | 处理 |
|------|------|------|
| build 报出莫名其妙的模块错误 | dev server 与 build 共用 `apps/web/.next` | 先停 dev server（用 `ss` 找端口 pid），再 build |
| `pnpm lint` 通过但其他包有类型错误 | lint 只覆盖 `apps/web` | 以 `pnpm build` 为准 |
| 迁移 checksum 失配、已部署库拒绝启动 | 改了 `schema.sql` 或历史迁移 | 只新增迁移，不改冻结文件 |
| 测试大面积失败但代码看起来对 | 存量测试写死了 v3.0 口径（槽位、45 天、买断） | 更新期望值并在 commit message 说明；不要删除覆盖 |
| 同一 `decision_id` 并发 GO 扣了两次配额 | 唯一约束在配额扣减之后才命中 | 先插入/占位 Project，再扣配额，或把冲突检测放在事务最前 |
| 公开页仍能搜到活跃机会 | S8 只做了增量发布，没做撤回 | 每轮对已 PUBLISHED 页重算资格，活跃即 DRAFT |
