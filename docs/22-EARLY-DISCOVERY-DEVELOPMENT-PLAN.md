# 新实体与早期搜索机会开发计划

日期：2026-09-30。状态：首个实施切片已本地完成，尚未部署；后续 P1/P2/P3/P4 仍按下文推进。

## 1. 目标与范围

让没有预设关键词的 Builder 获得有来源的新实体候选，知道哪些搜索意图尚未被满足，并能以有限成本开展试验，跟踪上线、首次观察到索引及真实搜索表现。

交付链：公开来源信号 → 实体与候选 → 意图假设 → 搜索验证 → 早期试验 / 持续观察 → 正式预测 → 用户项目结果。

不承诺提前固定天数、不保证排名、流量或收录。第一版不做自动建站、自动注册域名、多平台全量爬取或通用采集框架。测试使用隔离数据库，不向生产写入测试用户或候选。

## 2. 当前代码基线与必须修正的认知

- `apps/worker/src/discover-candidates.ts` 从已有 Autocomplete 历史扩展候选；空库没有上游入口，不能自行发现实体。
- `packages/services/src/scripts/ingest-google-trends.ts` 是 RSS 导入脚本，不是完整增长时间序列。
- `apps/worker/src/observe-opportunity.ts` 正式发布要求 Autocomplete 和 SERP 各至少 14 天；不能等同于实时新词预警。
- 同文件把 autocompleteGrowth 传入 `trendsSlope90d`，需修正来源语义，不能把建议词扩张标成 Trends 搜索增长。
- `apps/web/src/app/feed/page.tsx` 优先显示正式机会，候选位于下方；无数据时未区分未采集、采集失败、真实零候选。
- `packages/services/src/project.service.ts` 有 GSC 数据接收/汇总方法，但这不证明 Google OAuth 或周期同步已经接通；创建项目还存在无 verdict 时拼接 ID 的路径。
- 当前 schema/读取接口没有历史笔记描述的完整 workspace 私有研究模型。新增研究结果必须按当前登录用户建立所有权；公共来源事实可复用，用户研究结果不能无条件共享。

## 3. 分阶段工作与验收

### P0：生产与证据边界（预计 2–3 个开发日）

工作：
1. 明确早期候选、用户试验、正式预测三个概念；保留现有 14 天正式门槛。早期试验不伪造 verdict、不计入正式预测命中率。
2. 修正 Trends 字段误用；每个指标注明来源、时间范围、缺失原因。Autocomplete 数量不表示搜索量。
3. 为新研究链路建立 user_id 所有权，服务/API 按用户过滤；公共信号与私有研究关系分开。历史全局机会不自动分配给所有用户。
4. 移出 schema 中按邮箱 OR ID 自动级联删除的历史清理逻辑，普通部署只做增量迁移。已有生产数据先审计、备份，再按精确确认对象迁移，避免误删真实账号。
5. 建立最小迁移记录/事务执行方式；保留现有 Docker 与 PostgreSQL，不引入新基础设施。

验收：无历史的候选可保存但无正式裁决；用户 A 无法读取或修改用户 B 的研究；旧数据保留；部署重跑不重复删除或初始化业务数据。测试只覆盖本轮改变的主路径及跨用户失败路径。

### P1：无需关键词的持续发现（预计 5–7 个开发日）

首批采用“1 个 AIsa 适配器 + 少量官方来源直连”。AIsa 优先承载 Search/SERP 和可用的 Social discovery；Hacker News 官方 API 与许可允许的产品更新 RSS 直连。GitHub、Reddit、X、Product Hunt、新站 sitemap 放到后续按效果扩源，避免权限与配额拖住首版。

工作：
1. 在 `packages/collectors/src` 增加 `AIsaProvider`，先实现 Search/SERP；只有公开文档明确提供、且授权允许保存/展示时才启用 Social discovery。Hacker News 与 RSS 使用独立官方适配器。
2. 所有适配器输出统一的来源条目 ID、URL、标题、许可范围内摘要、源发布时间、首次采集时间、内容摘要 hash、provider、request hash 和成本记录。
3. 增量游标与去重；失败记录重试时间，限频退避。每次运行写来源成功/失败、时间、条目数、供应商和费用。
4. 在现有 worker CLI 增加发现任务，与每日预测封存分开，避免当天已封存后停止发现新候选。
5. 从信号提取新产品、模型、功能与用户任务，保留原文引文。模型提取是推断，不作为搜索需求证据；实体歧义暂不合并。
6. 记录系统首次发现与来源发布时间，不能宣称系统第一次看到就代表全球首次出现。空库从真实来源启动。
7. AIsa 不直接暴露给前端；供应商不可用时，单源失败只影响对应来源，不能把失败显示成“没有新机会”。

AIsa 准入门槛：在生产启用前核对 Search/SERP/Social 的字段、国家/语言/设备参数、分页、原始响应、价格、速率限制、商业存储和再展示授权。若缺少 URL、发布时间、排名或完整请求上下文，该接口只能作为线索，不能进入正式证据或评分。

替换条件：连续两周真实运行中，AIsa 的覆盖率、延迟、失败率、单位成本或证据完整性不达标时，保留官方/备用 provider；不得因统一 API 而删除可用的直连适配器。

数据增量：信号条目、实体及来源关联、用户候选记录；运行统计复用现有 collector_runs，只有缺少字段才增补。候选包含首次发现、支持来源、证据不足项和下次验证时间。

UI：Feed 顶部增加“新发现”，默认不要求用户输入词；可设置兴趣、忽略候选、进入验证。显式显示最近成功采集时间与来源故障。

验收：隔离空库不输入关键词，能从真实来源产生带原文 URL 的候选；同一批重跑不重复；来源失败不会显示成“今天没有机会”。在生产只运行真实采集。

### P2：意图生成与需求验证（预计 4–6 个开发日）

工作：
1. 每个实体按任务生成最多 6 个相关意图假设，例如使用、下载、替代、API；不机械拼出不适用的修饰词。
2. 分开存储模型假设与真实 Autocomplete/SERP 观测。生成词不因生成而成为“有人搜”。
3. 对优先候选调用现有 Autocomplete 与单一真实 Google 有机 SERP 采集器，固定市场/语言/查询参数，保留采集时间与来源。
4. Trends RSS 用作线索。若无可用的合规时间序列供应商，展示“增长未验证”；不伪造 90 天斜率，不阻塞其他验证链路。
5. 只有同源、同口径、覆盖可比的快照才计算变化；无基线/请求失败是未知，不填零。单独显示注意力、查询扩展、搜索增长。
6. 词按同一用户任务聚类，输出核心词、辅助词、搜索意图与证据；不以字符串相似直接合并歧义实体。

验收：能从一个真实实体看到完整意图验证表；假设、观察、增长未知的状态可辨；失败不产生正向需求分数。没有 Trends 凭据时系统仍能运行并显示限制。

### P3：供给缺口与早期行动卡（预计 4–5 个开发日）

工作：
1. 复用 SERP 采集，增加“结果是否满足该任务”的理由和引用；Reddit/GitHub/新闻类型本身不自动等于弱竞争。
2. 比较同口径 Top 10 的任务满足程度、专门工具数量及其变化；保留 SERP 不完整时的未知状态。
3. 综合来源时效、需求证据、任务缺口与竞争变化排序；显示排序理由。阈值是待校准规则，不显示虚构成功概率。
4. 早期行动卡包含：发现什么、支持什么、还缺什么、核心词、推荐页面形态、最小功能、建议复查时间及放弃条件。
5. 复用现有 projects，允许候选创建明确的试验项目；正式 GO 仍关联真实 verdict。不得用拼接的假 verdict ID 绕过外键。
6. 报告给出一页可实施任务清单；首次上线只做一个核心意图页面。早期提醒复用现有告警存储，默认站内提醒。

验收：用户能从不足 14 天的真实候选创建试验并明确知道商业/增长尚未验证；试验不进入正式预测战绩；正式候选仍按原门槛发布。

### P4：上线与 GSC 实际结果（预计 5–7 个开发日）

工作：
1. 项目填写目标 URL、核心查询及上线时间，校验 HTTP、robots/noindex、canonical、页面可抓取内容与 sitemap，所有网络访问防 SSRF。
2. 实现 Google OAuth、站点权限校验、凭据加密、断开连接与周期同步；沿用现有 ProjectService 和指标表。
3. 增量保存日级事实以准确计算 T+7/14/30；周表只做投影。总量用独立站点/页面查询，不把受截断的 query 维度行求和当完整总量。
4. URL Inspection 只查询索引状态。请求索引给出 Search Console 手工入口，不承诺通用自动提交；实现前核对 Google 当前权限和 API 能力。
5. 区分发现时间、用户声明上线时间、首次成功抓取检查、首次观察到已索引、首次曝光与点击日期。首次观察到索引不是 Google 精确首次索引时间。
6. 依据真实 GSC 新查询提出下一页建议，并保存用户采纳/忽略；不自动大量生成页面。

验收：真实授权站点完成同步、重跑幂等、断开后停止同步；未授权显示未连接；能复盘发现到上线/首次观察索引/首次曝光时差，且缺失数据保持未知。

### P5：真实试运行与质量校准（7–14 个自然日，后续持续观察）

- 邀请少量真实使用者，人工复核前 20 个候选的实体正确性、原文依据、搜索意图和 SERP 满足度；逐条记录通过/驳回理由。
- 统计来源发现延迟、有效候选比例、用户试验采纳、验证成本、失败率。没有结果样本不宣称预测有效。
- 上线后持续观察 30 天项目结果，报告样本数与选择偏差；比较仅 Trends 发现基线，验证上游发现是否确实更早。
- 低质量来源暂停；新增 GitHub 或其他来源必须先证明对有效候选有增量贡献。

## 4. 调度、成本与部署

供应商边界：AIsa 是可替换的聚合 provider，不是 EmeRadar 的事实层。EmeRadar 仍负责来源身份、证据分类、快照不可变性、成本账本、失败状态和用户可见限制。AIsa 可覆盖的 Search/SERP/Social 只替换采集入口，不能替换 HN/RSS 的来源归属，也不能替换 GSC 用户授权和结果回流。

- 沿用单 VPS、Compose、PostgreSQL、cron；首版不增加 Redis、常驻浏览器集群或多 worker 框架。
- 发现任务初始每 2 小时运行，候选验证每 6 小时，正式评分每日一次，GSC 每日同步；均受供应商配额约束。
- 起始每轮最多 20 条新信号、5 个待验证实体、每实体 6 个意图；先收集轻量事实再按优先级请求付费 SERP。这些是保守启动值，试运行后调整。
- 每日付费额度显式配置；未配置付费预算则暂停付费请求，不能沿用代码中隐含的每日 20 美元预算。
- 用宿主机文件锁串行执行部署构建与 worker；超时退出并记录失败，下一轮续跑。当前 1.6GB RAM 不同时运行多个重任务。
- 原始载荷设保留期，候选证据快照按审计需求留存；每周统计数据库/对象大小、调用费用，验证恢复备份。

## 5. 依赖与发布门槛

外部条件：确认 AIsa Search/SERP/Social 的 API 文档、价格、速率和商业使用/再展示许可；确认 HN/RSS 来源许可；可用的 SERP 凭据与费用上限；提取模型配置；用户自己的 Google Cloud OAuth 配置与授权站点。秘密只经 VPS 配置或 GitHub Secrets 传递。

实施顺序：P0 → P1 → P2 → P3；P4 在发现链稳定后接入；P5 从 P1 开始收集运行数据。工程量约 19–27 个开发日，供应商权限/审核和真实观测时间另计，不作固定交付承诺。

每期发布：定向现有测试、必要主路径/关键失败断言、类型/构建检查、隔离库迁移重跑、备份确认、灰度真实采集、核对公开 UI 与运行计数。不为计划引入新测试框架。

第一里程碑（P0–P3）：新用户无需输入词，能看到由 AIsa 或官方 HN/RSS 发现、带真实来源和 SERP 验证的候选，并开展有风险边界的试验。

第二里程碑（P4）：真实项目结果回流，形成发现 → 验证 → 试验 → 结果闭环。

## 6. 首个实施切片（2026-09-30）

- schema 不再按 Demo 邮箱或 ID 自动删除用户；来源条目使用独立 `discovery_items`，与正式 opportunity/verdict 解耦。
- 新增 HN 官方 API 与显式配置 RSS feed 的采集适配器，以及独立 `discover` worker 命令；来源条目包含 URL、发布时间、首次采集时间、内容/请求 hash，并以来源 ID + 条目 ID 幂等。
- 新增 `discovery_intents` 与 `generate-intents` 命令；每条来源最多生成 6 个带 `HYPOTHESIS` 状态的意图候选，未经过 Autocomplete/SERP 前不计为需求证据。
- 新增 `discovery_validations` 与 `validate-intents` 命令，按日幂等保存 Autocomplete/SERP 结果；只有真实观测到结果才将假设标记为 `OBSERVED`，失败保持可见。
- Feed 增加 New source discoveries 区域，明确显示来源、原始链接、时间和意图假设状态。
- 单源失败保留 `collector_runs` 错误状态，不折叠为零候选。RSS 只采集通过 `DISCOVERY_RSS_FEEDS` 显式配置且有权使用的 feed。
- Autocomplete 扩展增长保留为 `autocomplete_expansion_growth`，不再传入 Google Trends 的 `trendsSlope90d` 评分字段；无 Trends 序列时保持未知。
- AIsa 真实 endpoint 暂不实现：仍需官方 API schema、认证、价格及商业保存/展示授权；不得猜测供应商契约。
- AIsa provider 已实现为显式配置的可替换适配器；未配置或响应不符合标准 `items` 结构时失败并记录原因，不折叠成零候选。生产启用前仍需供应商文档核验。
- 本地验证：`@emeradar/db`、`@emeradar/collectors`、`@emeradar/worker`、`@emeradar/web` TypeScript/生产构建通过，collector 现有 8 项测试通过；数据库迁移和真实外部采集尚未执行。
